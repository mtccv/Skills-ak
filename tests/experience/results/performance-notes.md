# Phase 14 有限只读性能记录

采集日期：2026-11-08（Asia/Shanghai）。这是本阶段的有限服务测量，不是 Final QA 2.0、负载测试或生产 SLO 验收。

- 实际环境：WordPress 7.1.4、MySQL 8.0.46；PHP 8.3.36 / 8.4.27；schema 1.9.0、33 张 Core 表，无持久对象缓存。
- PHP 8.3 保留夹具：89 个 Skill（所有状态）、173 条译文、206 个原生用户；PHP 8.4：74 个 Skill、147 条译文、173 个用户。两环境均有 42 篇已发布帮助教程，每种语言 21 篇。数据规模不同，不能据此比较 PHP 性能优劣。
- 每个版本执行 7 个服务范围 × 2 种语言，共 14 个独立 PHP 进程；每进程仅测一次首次调用和一次同请求重复调用。两份最终 JSON 共 56 个时间/查询样本，不计作 56 条业务验收用例。
- WordPress 启动、样本选择、身份准备、规模查询不计时；数据库和操作系统缓存未清空。服务源码哈希随 JSON 保存，两环境一致，各环境内部样本数据规模一致。
- 读保护在 `wp-load.php` 后安装，测量期间禁止 SQL 写入、命名锁、文件输出和外部 HTTP/邮件。最终记录均为零写入阻断、零 HTTP、零邮件尝试。没有生成新夹具或修改业务配置。

| 服务范围 | PHP 8.3 首次/重复 SQL | PHP 8.4 首次/重复 SQL | 首次实测耗时范围（两语言/两环境，ms） |
|---|---|---|---|

| 同一教程 8 个普通 postmeta 读取 | 2 / 0 | 2 / 0 | 0.269–0.400 |

同一范围的中文和英文 SQL 次数一致。PHP 8.3 首页多一个分类祖先的批量递归 SELECT：该环境存在六个可见层级分类，PHP 8.4 的该夹具没有可见分类。首页范围只测实际 catalog 前置查询，不包括发现模块、模板渲染或 HTTP 请求。Skill 样本有两个公开译文，暂无相关教程；订阅样本确有本人偏好，引导样本完成条目为零。不能把未命中的推荐分支算作性能已验证。普通 postmeta 的 8 次读取使用 2 个首次查询，重复查询为零，没有出现每次读取附加查询的现象；此有限观察不能代替全站 N+1 检查。

账户状态读取保留实时权限/状态查询，重复调用未缓存成零查询；本次没有为减少这些查询修改业务权限或缓存语义。

执行过程记录：PHP 8.3 第一轮在分类祖先的合法 `WITH RECURSIVE … SELECT` 被测试辅助脚本过窄的白名单阻止，未写数据库；已限定放行现有只读 CTE，继续拒绝写语句。紧接着一次启动尝试返回 exit 255，原始诊断未保存，原因无法确认；同一命令立即单独重跑成功，在协调其他夹具测试结束后完整 14 进程最终测量也成功。该瞬时中止不能被描述为已定位并修复的产品错误，最终 JSON 只包含完整成功的有限测量。

复现：先确保独立 QA 服务没有其他测试写入或切换主题，再分别运行 `python3 tests/experience/performance.py --runtime 83 --container-script /repo/tests/experience/performance.php` 和 `--runtime 84`。脚本限制本地 QA 数据库名，不适用于生产运行。
