## 1. 设计目标与约束

发现、学习、评价、收藏、贡献采用同一套信息层级。白色和中性浅灰保留大面积内容背景，深灰承载正文，陶土棕只用于小面积主要行动与当前选中状态；不以大面积渐变或装饰代替来源、兼容性、安装边界与风险证据。首页是专业资源平台，教程与社区是能力扩展，不把网站画成传统博客。

- 内容真实：空结果不填假资源；未知评分、License、依赖、作者或统计不展示成 0、MIT、安全、已验证或真实作者。演示页的样本仅用于设计评审。
- 状态准确：资源发布审核、社区评价审核、静态/AI 风险检查使用不同标签，不用一个绿色勾号包办“可信”。
- 任务优先：目录先搜索与筛选；详情先理解用途与来源；账户先处理验证/待办；后台先待审、失败和下一步。
- 渐进增强：生产保持 PHP SSR + WordPress 模板；Tailwind 管视觉，Alpine 管适度交互。无 JS 仍能导航、阅读与通过服务端表单完成关键操作。
- 前台与后台共享语义、状态、文案原则，**不共享强制外观覆盖**。WordPress 原生菜单、表格、Notice、用户配色和屏幕选项保留。
- 免费使用、可退出的引导、清楚的赞助标识、默认关闭营销订阅；不得以设计暗示付费墙或强制订阅。

## 4. 字体、字号、空间与形态

无外部字体依赖。主栈：`Inter`（仅本机已有时）、`ui-sans-serif`、系统字体、`Segoe UI`、`PingFang SC`、`Microsoft YaHei`、sans-serif。代码采用系统等宽。中英文按实际字形测试，不用中文专用断行硬编码到英文。

| 层级 | Desktop | Mobile | 行高与限制 |
| --- | --- | --- | --- |
| Hero H1 | 56px / 700 | 36px / 700 | 1.2；Tablet48；可自然增加行数，不固定高度裁切 |
| 页面H1 | 42px / 700 | 30–32px / 700 | 1.2–1.3；详情长名称换行 |
| 区块H2 | 30px / 700 | 24px / 700 | 1.3 |

| 说明/正文 | 16px | 16px | 中文1.8–2、英文1.65–1.85；文章约65–75字符行宽 |
| UI正文 | 14–15px | 14–15px | 1.6；标签不是正文替代 |
| 元数据/标签 | 12–13px | 12–13px | ≥1.4；错误、主要操作不得降到此档 |

间距以4px为基本步长：4、8、12、16、20、24、32、40、48、64、80。卡片内边距24（紧凑20），移动16–24；区块上下64/移动48；表单字段间20–24；图标和文字间8。基础字重400/500/600/700，不用人为缩放文字塞入空间。

圆角：小标签6、输入与按钮10、卡片16、大Hero面板20、装饰24；头像圆形，表格不强加大圆角。阴影：默认卡片依靠边框；Hover `0 8px 24px #1118270A`；Hero `0 20px 60px #11182712`；弹窗更高，禁止每个组件都漂浮。

图标：24×24画布，20px常用显示，1.6px统一描边；装饰`aria-hidden`，纯图标操作必须有本地化可访问名称。评分同时输出数值与人数，星形仅辅助；未知评分显示“暂无已审核评价”。

## 5. 页面布局与组件合同

内容宽度1280指**实际可用内容**，不含外边距：`min(1280px, 100% - 2 × gutter)`；gutter移动16、Tablet24、Desktop32。1440时左右80，1920时左右320。Desktop≥1024，Tablet768–1023，Mobile<768；不以设备名称替代CSS viewport。

| 布局原型 | 组件及阅读顺序 | 移动规则 |
| --- | --- | --- |
| 发现首页 | 品牌导航→Hero→独立搜索→分类→榜单/精选/更新/教程→投稿→Footer | 单列；Hero文案先于装饰；操作换行；按模块隐藏/排序不改变语义 |
| 资源列表 | H1+关键词→筛选240px/结果网格；结果数、排序、分页 | 筛选原生details内联展开；Tablet2列，Mobile1列；筛选不制造双滚动 |
| 内容详情 | 标题/来源动作→正文+320px信息侧栏→评价/相关内容 | 主要动作前置；正文先读，附加来源面板随后；代码局部横滚 |
| 账户 | 页面标题/待办→240px侧导航+内容；短统计4/2/2列 | 导航details；统计仅短标签数字，辅助说明移到组外；主要任务优先 |
| 运营后台 | WP顶栏侧栏→标题/筛选/待办→表格/诊断；权限决定入口 | 原生窄屏菜单、优先列与展开详情；不把长表格强缩成不可读文字 |

### 5.1 按钮、链接与输入

- 主按钮每个任务区一个主优先级，白字陶土棕底；次按钮白底边框；文字动作有颜色/下划线Hover；危险操作明确动词+对象，独立确认，不以红色主按钮诱导。
- 前台最小触控44×44；文字可换行、按钮可增高。Hover、Focus、Active、Disabled、Loading均独立；Loading禁重复提交并保留操作文字，不能仅旋转图标；失败后恢复操作。
- 输入框永久可见label，placeholder只给例子；必填文字明示；说明在字段下。无效保留用户输入，字段`aria-invalid` + `aria-describedby`关联错误；提交错误总览可跳转字段。成功先确认持久化再显示，不以按钮点击假设保存。
- 密码可显隐，有对应名称与`aria-pressed`；粘贴/密码管理器可用；认证失败统一提示，防账户枚举；验证码/验证邮件不显示真实令牌或邮箱完整列表。
- 长URL、SHA、路径可复制并局部换行；复制反馈不等于执行/安装；来源命令未经核实不得编造。

### 5.2 卡片、表格与状态

| 组件 | 默认与交互 | Empty/Error/限制 |
| --- | --- | --- |
| Skill卡片 | 图标、名称链接、用途、平台/标签、来源摘要；可用时收藏/评分；动作不嵌套进整卡链接 | 未公开目标不能残留旧标题/正文；不可用收藏给通用占位+移除，不泄露草稿 |
| 教程卡片 | 图解、主题、真实标题、语言、阅读入口 | 图片缺失用本地几何占位，不伪造作者/阅读时长 |
| 统计卡 | 数字+单位+口径/窗口+更新时间；允许短标签 | 查询失败不是0；不足样本/未知显示说明；不补造历史 |
| 列表/表格 | 语义caption/th/scope，键盘排序，筛选状态，逐行与批量反馈 | 移动保留对象、状态、关键动作；次字段展开或有标识横滚；行选择不等于全库 |
| 分页 | 当前页、页码/前后、结果总数；链接保留允许参数 | 无结果无无效下一页；生产SSR URL可分享；不默认无限滚动 |
| 状态标签 | 文字+可选图标+色彩；如“待内容审核”“待评价审核”“风险Unknown” | Published≠安全；AI草稿≠人工批准；审核通过不自动代表版本源已核验 |

### 5.3 弹窗、通知、反馈

弹窗只用于简短确认/评价；长投稿和复杂编辑是完整页面。标题与说明关联，可Esc退出，打开焦点进入，Tab限制在模态内，关闭回到触发者；危险确认默认焦点在取消。移动宽`100%-32px`，最大高90dvh、内部可滚动，底部按钮不挡住字段。若未来使用抽屉，仍需同样焦点/遮罩/关闭规则；当前目录采用内联details，无假装模态的半成品。

Toast用于可恢复轻操作，`role=status`，短文本，6秒仅原型演示；重要失败/权限/不可恢复错误用持久Notice，不自动消失。成功页不承载机密参数、不进入Sitemap；验证码/私有通知不得出现在公共HTML、缓存或分析事件。

| 状态 | 设计与交互 | 验收 |
| --- | --- | --- |
| Loading | 与布局匹配的骨架+载入说明；`aria-busy`/status；减动画模式静态 | 不能无限加载掩盖错误；页面级/区块级作用域明确 |
| Empty | 原因+可执行下一步；首次收藏、无结果、未开放各用不同文案 | 不显示假统计或可操作但未实现的生产按钮 |
| Error | 用户可理解原因、重试/返回、保留输入；后台可显示脱敏关联ID | 不泄露SQL、堆栈、Token；失败不显示已保存 |
| Partial | 可用内容保留，失败模块局部解释 | 不把未完整扫描标为完整、不推断来源删除 |
| Missing translation | 标明所缺语言，指向确实公开的原文或目标语言目录 | 不拼接假译文、不输出无效hreflang、不跨语言错误canonical |
| Unauthorized/expired | 登录或验证入口、安全返回地址、原提交数据安全处理 | 私有URL noindex+no-store；不能靠前端隐藏保护数据 |

## 6. 首页可扩展架构合同

### 6.1 边界与分层

本轮“基础架构”落实为**可评审的数据/渲染合同和可运行静态演示**，不把生产首页重构或配置保存偷偷放入设计阶段。首期只有`modern-saas`已设计；后续新风格必须先实现并注册，再出现于选择器，禁止空选项/任意模板路径。

```text
运营配置（zh / en、模块显隐/顺序/来源/copy）
          ↓ 验证、修订、权限、语言/公开门禁
稳定模块读模型（现有PublicCatalog / 教程 / P9–11真实统计）
          ↓ 与风格无关的有限数据，不允许直接SQL
风格注册表（modern-saas V1：允许模块、模板、token、版本）
          ↓ PHP SSR，现有URL/SEO/WPML，适度Alpine增强
前台页面 / 有权限且noindex no-store的预览
```

Hero、搜索、分类、Trending、Editor’s Picks、Recently Updated、Top Rated、教程、投稿各有稳定模块ID；一模块一个有限数据合同，模板只负责表现。原型ID分别为`hero/search/categories/trending/editors/recent/rated/tutorials/contribute`，正式枚举与来源合同集中在[前台规范§5](FRONTEND_DESIGN_SPEC.md)，不得多处独立解释。

风格与运营内容分离：`presentation.style_id`全站首页共享；`locales.zh/en.modules`各自拥有copy、显隐、顺序和允许的source选择。模块可独立隐藏/排序，保留可访问导航和唯一H1。共享风格变更要审核并冻结两语言配置；单语言运营内容更新不得把另一语言未发布草稿带上线。

示意结构（**不是本轮新增生产option或迁移**）：

```json
{
  "schema_version": 1,
  "revision": 12,
  "presentation": {"style_id": "modern-saas", "style_version": 1},
  "locales": {
    "zh": {"modules": [{"instance_id": "main-hero", "type": "hero", "enabled": true, "position": 10,
      "source": "localized_editorial", "limit": 1,
      "copy": {"title": "经管理员确认的中文标题", "description": "独立中文描述"}}]},
    "en": {"modules": [{"instance_id": "main-hero", "type": "hero", "enabled": true, "position": 10,
      "source": "localized_editorial", "limit": 1,
      "copy": {"title": "An independently reviewed English title", "description": "English copy"}}]}
  }
}
```

正式完整字段、枚举、内容数量上限、公开筛选以及无数据行为见前台规范；示例不允许直接变成任意JSON编辑器。P11榜单只用真实合格数据；P8–10无服务时模块不启用。Editor’s Picks复用已有`featured`唯一标识，未来集合扩展不能再建第二个互相矛盾的精选开关。Recently Updated必须代表公开内容更新，不能沿用采集触碰的`updated_at`伪造热度。

### 6.2 后台交互与发布

WP原生“首页外观”面板：风格选择（仅已开发项）→中文/英文内容标签→模块清单与显隐→上移/下移（键盘可用，拖拽仅可选增强）→有限来源/条数/copy→Desktop/Tablet/Mobile预览→保存草稿→校验与发布确认。字段失败留在当前语言并保留输入；空来源有反馈，不展示公开草稿内容。

- 草稿修订与已发布快照隔离；保存有base revision/CAS，发生并发冲突需重载或逐项比较，不静默覆盖。
- 发布前验证风格、模块ID/重复、允许字段/数量、各语言copy、数据服务可用与公开门禁；原子切换published pointer，失败维持原首页。发布后失效相应语言/模块缓存，审计记录操作者/时间/修订。恢复历史必须重新验证，不回滚业务Skill。
- 预览有授权、Nonce/短时令牌及服务器权限；私有预览禁止共享缓存、搜索索引和Sitemap；设备宽度改变展示，不产生三套内容。
- 定时切换仅预留合同：不可变已审核revision、站点时区/UTC、到期校验、幂等job key、执行锁、失败状态/取消/恢复与审计。当前原型明确“暂未开放”，没有真实调度。若将来执行时风格缺失/版本不兼容/能力不足，保留当前快照并报错，不发布半份配置。
- 正式保存/草稿发布属于P12运营扩展；P8–11先按统一模块读模型逐步接入真实能力。若希望提前生产实现，需另行安排明确范围，不能挤入本轮。
- 不提供自由画布、任意HTML/CSS/JS、远程模板、任意URL数据源、任意SQL、Elementor/Divi或完整页面构建器。

原型后台仅在当前页面内存保存示例草稿，通过同源iframe演示模块变化；刷新重置，未访问WordPress接口，也未生成生产首页配置。

## 7. 中英文、SEO与内容策略

- 同一Skill稳定ID关联中英内容；显示语言由合法路由/Adapter决定，不能用浏览器语言悄悄覆盖显式选择。
- 完整句子翻译，避免字符串拼接；标题/按钮/标签预留约1.5–2倍长度，中文不固定字数断行；数字/时间按locale，UTC来源不伪成本地时间。
- 当前有效过滤条件可保留，分类/标签必须映射目标语言有效项，缺译/无效条件反馈；教程按配对关系跳转，不按相似slug猜测。
- 正式SEO复用现有系统：每语言独立Title/Description、自引用Canonical、真实可访问译文hreflang、受控x-default、插件互斥输出；新账户与私有流程noindex，不能靠robots.txt屏蔽后误以为搜索引擎会读取noindex。
- 原型只有`noindex,nofollow`与演示标题，无真实canonical、hreflang、JSON-LD或Sitemap；静态演示不代表SEO集成已测试。
- 用户体验评价默认不自动翻译；用户昵称不代替来源作者；个人语言偏好不暗示邮箱、国籍或营销许可。

## 8. 开发交付与验收门槛

本规范和四份配套文件为后续P8–14共同验收基准。功能PR必须引用涉及页面/组件/状态，提供两语言桌面和移动截图、必要交互/无障碍证据。视觉偏离应说明具体原因并同步规范，不能以“功能已做完”跳过设计；不为凑视觉改动重写稳定业务。

1. 布局：检查1440/1024、768、390/360，超长英文/中文、200%缩放与320px reflow；宽屏内容不无限拉伸，无页面级横向溢出；单独代码/表格横滚可理解且可用键盘。
2. 组件：按钮、输入、卡片、表格、标签、弹窗、通知均覆盖Default/Focus/Hover/Disabled/Pending/Success/Error；状态文字和权限吻合。
3. 响应式：导航不遮挡；细节主要动作先于长正文；筛选、页码、表单44px目标；移动账户短统计可2列，长解释独立展示；WP后台保留原生可访问性。
4. 内容：无伪造统计/推荐/安全认证/安装命令；不可公开Skill在任何新入口保持门禁；缺译不误导；无第三方追踪字体/图像默认外发。
5. 多语言：两语言独立文案、长标题换行、语言切换可回到关联实体或明确回退；正式SEO复用既有接口，不重复输出。
6. 首页：逐模块渲染/空/失败；中英独立copy；已实现风格选择；预览与发布隔离；未来实现CAS/权限/失效测试后才宣称配置上线。
7. 交付：沿用现有Tailwind/Alpine/SSR，代码与组件集中维护；不得将本原型的示例记录或内存交互接入正式数据库/主题。

**本轮验收范围**：五个重点页面的可打开静态视觉、两语言/设备/状态演示、设计文档与浏览器记录。其余页面为可执行设计规格，尚未绘制独立完整原型；账户、邮件、评分、收藏、WordPress保存、数据库权限和外部API均不是本轮功能测试。完整已执行/未执行范围以原型README为准。
