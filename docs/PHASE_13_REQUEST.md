## 二、先处理 Phase 12 的运营概览性能遗留

Phase 12 报告提到运营概览查询次数偏高。

本阶段先进行一次有边界的检查与优化：

1. 在可复现的测试环境记录运营概览请求的查询数量、数据规模和测量方式。
2. 定位重复统计、逐行查询、重复加载或不必要的权限范围外查询。
3. 优先使用批量查询、聚合复用、分页和合理的请求内缓存。
4. 确需跨请求缓存时，明确权限隔离、失效条件和统计更新时间。
5. 公开状态、用户暂停、审核撤回等安全判断不能依赖过期统计缓存。
6. 对比优化前后的实际结果，确认统计含义和权限范围没有改变。

不要为了降低查询次数删除必要检查，不要编造性能提升比例。

如果环境不足以测量，明确记录未验证项；不能仅凭代码改写就宣布性能问题解决。生产规模压测仍留到 Final QA 2.0。

## 三、赞助展示能力：默认关闭

增加最小的、人工管理的赞助展示能力，复用现有首页和内容组件。

设计必要配置：
- 展示位置。
- 赞助名称。
- 标题和简短说明。
- 合法可用的图片或标识。
- 目标链接。
- 内容语言。
- 生效和结束时间。
- 草稿、启用、暂停、到期等状态。
- 内部审核及操作记录。

重要规则：

1. 默认关闭，不自动创建赞助商、素材或展示记录。
2. 管理员没有配置并明确启用时，网站保持正常免费内容展示。
3. 展示时必须清楚标注“赞助”或“Sponsored”，移动端也不能隐藏标识。
4. 赞助与编辑精选分开，不将 sponsored 混入 featured 的业务含义。
5. 赞助不能影响 Trending、Top Rated、Most Favorited 等自然排行榜。
6. 赞助不能改变评分、收藏、浏览等真实统计。
7. 赞助不能赋予作者认证、来源认证、安全认证或发布权限。
8. 推荐某个 Skill 时，必须重新通过现有 PublicCatalog 的当前语言公开检查。
9. 生效和到期检查应作用于实际展示；不能仅依赖 Cron 恰好按时运行。
10. 没有完整内容时，不生成空的公开赞助页面或无价值 Sitemap 项目。

只提供有限预设位置和受控内容，不开发广告交易平台、竞价系统或任意页面构建器。

## 四、免费权益扩展接口

检查现有账户与权限服务，提供一个最小、可扩展的业务权益查询边界。

当前实现只有已确认的免费使用规则：
- 访客按现有规则浏览和搜索。
- 已验证用户按现有规则收藏、评价、投稿和管理个人资料。
- 管理能力继续使用明确的 WordPress Capability。
- 账户暂停、邮箱未验证及对象归属限制继续生效。

要求：

1. 不建立独立账户体系。
2. 不创建付费会员套餐、价格、到期扣费或自动续费逻辑。
3. 不为未来需求提前创建订单、账单、钱包和支付表。
4. 不把“已注册用户”改成“付费会员”。
5. 不新增可以任意授予管理能力的通用权限配置器。
6. 未来权益来源即使扩展，也不能绕过内容审核、邮箱验证、对象权限或账号限制。
7. 不增加主题联网授权、激活码或许可证服务器依赖。
8. 当前免费功能的可用范围不能因本阶段而缩减。

接口应简单且有文档，不为了预留而搭建完整商业规则引擎。

## 五、原创 Skills 与套装展示

复用现有：
- 人工录入的 Skills。
- 稳定 Skill ID。
- 双语内容和人工审核。
- 编辑集合及关联关系。

可以提供原创资源、资源套装的分类或展示入口，但必须满足：

1. “原创”标识具有可核查的依据，不能靠管理员勾选就声称拥有权利。
2. 来源和许可不明确时保持待核实，不自动标注原创或可商业再分发。
3. 套装只组织现有资源，不复制一套“商品版 Skill”。
4. 套装中的每项资源仍需满足当前公开条件。
5. 没有真实内容时，入口保持隐藏或草稿，不发布虚构套装。
6. 不接入购买、结账、付费下载、压缩包执行或远程安装。

继续提供正常的免费发现和学习体验。

## 六、企业服务说明与咨询入口

复用现有双语页面及 Contact／私有 Inbox，增加必要的企业咨询类型。

允许：
- 展示真实的服务说明。
- 收集必要的联系信息和需求描述。
- 进入私有人工处理流程。
- 复用现有权限、限流、通知和处理记录。

不允许：
- 将咨询提交描述为订单创建、合同成立或服务已交付。
- 虚构客户、合作案例、服务成果和报价。
- 自动触发收费 API、采集任务或外部服务。
- 自动把咨询邮箱加入营销名单。
- 将咨询正文、邮箱等个人信息写入公开统计。
- 为企业咨询另建第二套联系收件箱。

Contact 与会员 Skill 投稿的权限规则保持各自原有边界，不因增加企业入口而混用。

## 七、最小展示与点击统计

仅在真实启用对应展示后，复用现有统计系统记录必要事件。

明确区分：
- 展示次数。
- 点击次数。
- 按既定规则去重后的事件。
- 实际收到的咨询记录。

要求：
- 记录统计起点、窗口、去重规则和限制。
- 不把点击称为购买，不把咨询称为成交。
- 不计算虚构收入、付费用户数或商业转化率。
- 不记录不必要的个人浏览轨迹。
- 不向合作方开放用户清单、邮箱或个人行为数据。
- 统计失败不能阻断正常页面或链接使用。
- 点击追踪不得形成可传入任意目标地址的开放重定向。
- 不允许通过新增商业事件修改自然排行榜的数据和权重。

不得引入第三方追踪脚本、广告像素或跨站画像作为默认功能。

## 八、后台、前台及安全要求

后台继续使用 WordPress 原生界面，复用已有管理组件。

能力按职责隔离：
- 配置赞助展示。
- 查看相应汇总。
- 处理企业咨询。

默认只给管理员必要权限；不能因为某人可以审核投稿，就自动允许其配置赞助或读取咨询隐私。

所有操作进行：
- 请求方法检查。
- Capability 和 Nonce 验证。
- 对象及状态检查。
- 输入验证和输出转义。
- URL 和图片资源限制。
- 必要的修订冲突与重复提交保护。

不允许保存任意 JavaScript、跟踪代码或可执行模板。不因赞助链接配置而自动抓取任意 URL。

前台继续遵循已确认的设计：
- 白色、浅灰色背景。
- 深灰色文字。
- 陶土棕 #AD5E48 适量强调。
- 专业、紧凑的 Skills 资源目录风格。
- 中英文及 Desktop、Tablet、Mobile 完整适配。

预览仍是私有预览，不能被公开搜索、Sitemap 或共享缓存泄露。
