# AI 内容生成与人工审稿

Phase 6 在原有 Core 中注册 `ai` 模块，使用 Phase 5 已采集、带完整来源绑定及 Blob SHA 的 Skill 快照。人工录入但尚无采集快照、归档/拒绝的 Skill、缺失来源或归档仓库不能直接生成。旧版本缺少 File SHA/仓库路径绑定时，应先完成一次 Phase 5 扫描；不伪造历史证据。

## 建立任务

1. 按 [API 配置](API_CONFIGURATION.md) 保存模型配置和服务器 Key。AI 全局队列默认暂停、配置默认停用，准备好后分别启用。
2. 打开 **AI Skills Hub → AI Generation**，输入一个或最多十个 Skill ID，选择模型配置和生成范围。表单提交只保存快照与任务，不在该页面请求中调用模型。
3. 选择完整中英文、单独中文、单独英文、双语摘要或双语使用场景。局部重新生成只建立新的独立建议，不覆盖以前的 AI 草稿或人工内容。
4. 在历史列表筛选任务状态/Skill，查看详情、失败原因、来源 SHA、模型、Prompt 版本、请求次数、Token、耗时和估算成本。重复提交相同表单复用原任务；同一 Skill 最多一个活动任务，已有任务不会因新请求变更范围或模型。

## 输入与草稿

发送给 AI 的输入只包含经过白名单选择的公开来源：名称、原始 description、SKILL.md、仓库/路径、SHA、License 线索、已有平台标签、静态检查、已有分类标签候选及可验证的目录元数据。人工译文、编辑基线、API Key 和任务控制字段不发送。常见凭据模式会脱敏，但不能承诺自动识别所有误提交到公开仓库的敏感信息。

只有目录清单与静态检查 Commit 对应时才携带该 Skill 目录的树元数据。目录超过 200 项则省略树并标明不可用；不会将部分目录冒充完整结构。候选分类/标签各取有界的前 200 项，未包含的词仍只能成为建议。

结构化来源总量上限 64 KiB，任务快照（含人工内容比对基线）上限 1 MiB；超限明确拒绝，不静默截断后编造结论。来源最多 512 KiB 是采集限制，不代表全部内容都能在本阶段一次发送给 AI。

完整草稿包括：

- 中文标题、简介、详细介绍、功能、任务、场景、安装初稿、环境依赖、限制及风险提示。
- 同一 Skill ID 对应的英文标题、摘要、介绍、功能、任务/场景、安装、要求、限制和安全说明。
- 已有主/次分类、标签、平台及场景建议；新词仅列为建议，不建表项或自动关联。
- AI 风险等级 Unknown/Low/Medium/High、引用证据、解释和局限；原静态扫描另行保留。

JSON 解析严格检查字段、语言范围、类型、长度、重复键和证据。安装命令必须逐字出现在来源原文及其引用中；未知安装方式/依赖/平台应写待核实，不能凭常见习惯补全。引用存在不等于语义正确或命令安全，仍需人工核对。语言字符检查仅能拒绝明显错语言，不能代替专业双语校对。

## 比较、编辑与采用

详情页分别展示原始 GitHub 文本、静态检查、不可变 AI 原始结果、可编辑人工草稿及当前人工/已审核译文。所有远程文本按文本转义显示；不会执行 Skill 或模型生成的代码。

1. 核对来源、安装命令、License、依赖和风险证据；在人工草稿区修改中文/英文标题、摘要或正文，保存后留下新的审核操作快照。
2. **采用只填充明确选中的空字段**。已有非空人工字段、slug 和 SEO 字段不会被该流程覆盖。需要合并已有内容时，可在原有 Skill 编辑器中由编辑人员逐项处理，保留常规修订和审核保护。
3. 使用场景属于局部正文建议，只供保存/比较和在原编辑器人工合并，不能把片段自动替换整篇正文。
4. 采用前重新检查生成草稿修订、Skill 修订、完整译文基线和来源指纹。来源同步或人工编辑已经改变记录时，旧草稿不能直接采用；应重新生成或在原编辑器核对合并。
5. 采用成功后 Skill 进入 pending / 待审核，当前修订增加；这不发布内容。新翻译没有自动生成的 slug，应在 Skills 编辑器补充并提交正常 Reviews 审核。另一语言可以按既有规则缺译，不造假内容。
6. 可拒绝 AI 草稿，保留历史。接受/拒绝关闭该份建议的采用流程；未选字段仍可在历史中查看，不会在后续重新生成时静默应用。

分类、标签和平台建议通过现有管理页面人工确认、创建和关联；优先核对已有词条，避免同义重复。AI 风险不会改写 Skill 的人工风险级别，不替代静态扫描或正常审核，也不是安全认证。

## 任务、重试和费用

WordPress Cron 事件 `aish_ai_tick` 每分钟最多执行一个 AI 请求，持有独立全局锁；不依赖 Action Scheduler。WP-Cron 需要流量或现有 Cloud 中受控触发，低流量/禁用 Cron 时会延迟。租约 120 秒、初始任务期限 48 小时、最多三次请求尝试。人工恢复/重试会重新设置 48 小时的期限，但不重置请求次数。每批最多十项，但每项独立恢复和记账。

全局暂停阻止领取新任务；单项或批量可暂停/恢复排队任务、取消未开始的任务。正在执行的 HTTP 请求不会被虚假声明为取消；暂停后当前请求可能完成，其结果和用量仍记录。主题停用清除 AI Cron，保留配置、任务、草稿和历史。

在发送前持久化尝试记录。明确限流/服务错误允许退避重试；网络超时、连接中断或 worker 消失导致结果不明时，记录 `uncertain`，由管理员先核对供应商请求/账单，再通过明确确认手动重试。不能承诺请求从未发生或没有费用。总尝试数达到上限需要新建请求，历史仍保留。

Token 来自供应商响应，缺失时显示未知。已获得响应但草稿 JSON 无效，也保留能验证的用量。费用由冻结的管理员单价计算，统一标记 USD **估算值**，不含供应商缓存、阶梯价格、折扣、工具或其他额外账单项。金额上限是请求前的保守估算检查；不能约束不遵守参数或不同计价规则的第三方账单。未知用量不按零费用累计，开启金额预算时会阻止预算不明的续试。

## 权限与记录

配置及全局暂停需要 `aish_manage_ai_settings`；任务生成/历史需要 `aish_generate_content`。连接测试同时需要这两种能力。人工草稿编辑/采用/拒绝 UI 还需要 `aish_manage_skills` 和 `aish_review_skills`。`manage_options` 管理员兼容这些能力；所有写操作要求 POST、nonce，采用/重试有明确确认。

`ai_jobs` 保存冻结输入、原始 AI 草稿、当前人工草稿及任务状态；`ai_attempts` 保留每次请求的用量/状态；`ai_reviews` 追加人工修改、采用或拒绝的快照、操作者、时间和修订。没有第二套 Skill ID。后台默认每页 25 个任务，详情显示最近 100 条人工操作，历史行不会自动删除。

本阶段仅完成 PHP、构建和隔离 Mock 检查，**没有运行真实 AI API、MySQL、WordPress、浏览器或端到端验收**。准确结果见 [Phase 6 报告](PHASE_6_REPORT.md)；真实运行验证留 Final QA。
