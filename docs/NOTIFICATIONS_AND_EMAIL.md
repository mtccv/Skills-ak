## 我的通知

`/zh/account/notifications/`、`/en/account/notifications/` 只读取当前登录账户。支持类型筛选、分页、未读数量、单条已读和本页最多 20 条批量已读（服务端一次最多 50 个明确 ID）。提交时仍检查所有权、Nonce 和账户状态；请求中的用户 ID 不能决定数据归属。

通知文案来自固定事件代码，不回显原始内容快照、举报人或管理员备注。关联入口在读取时按当前用户、对象类型、归属和最新状态重新生成；对象撤回、删除、进入隐私清理或不可访问时显示不可用，不保留可绕过权限的历史 URL。目标页面再次验证权限。

账户通知和可选社区/投稿通知偏好复用受保护用户元数据。偏好影响今后的可选站内账户通知、社区通知和投稿/开发者通知；已经生成的历史通知继续保留。验证、改邮箱、改密码、会话撤销和隐私申请的必要通知不受可选站内偏好影响。关闭可选通知不会取消安全凭据流程或篡改已经发生的业务审核；保存通知偏好只验证当前公开选择且不写该字段；公开选择由既有开发者资料流程负责。旧接口传入的公开值与最新状态不一致时拒绝保存，避免并发覆盖。通知列表与用户设置属于私有、不可缓存页面。

## 邮件状态的准确含义

| 状态 | 含义 |
|---|---|
| queued | 已持久入队，尚未执行 |
| retry | 确认可恢复的有限重试，带下一次运行时间 |
| claimed | Worker 已领取；可能尚未发送 |
| sending | 已进入传输调用阶段 |
| accepted | 传输返回受理；**不代表收件人收到** |
| failed | 明确终态失败；凭据密文已销毁 |
| uncertain | 调用超时/异常等导致结果不确定；不能盲目重发 |
| cancelled / expired | 已取消或到期；不能重新恢复旧凭据 |

尝试次数是领取次数，可能包含发送前中断，不能作为送达次数。后台统计只按实际保留的队列记录和明确 UTC 窗口计算，没有可靠送达回执时不显示送达率。

## 允许的恢复

后台只操作现有 outbox，不在管理页面发送邮件。暂停与 Worker 使用同一队列锁；正在执行的 Worker 未释放时操作明确失败，不能假报已暂停。恢复队列不启用 GitHub 或 AI，也不重新执行已经成功的业务处理。

手动有限重试仅适用于现有 `retry` 项：尚未被新 Worker 领取、有效期内、密文仍存在、下一次运行时间尚未到、明确传输拒绝且领取次数小于 3，或发送前中断且领取次数小于 5。已经到运行时间的项交由 Cron 领取，后台不额外发出第二次请求。重复点击不能创建第二封邮件。结果不确定和已受理项禁止重发；终态密文不会被重建。需要新验证或重置邮件时，用户走原有一次性 Token 和重发限流流程。

到期/中断恢复按既有分批状态机执行，每类最多 100 条；暂停期间仍允许凭据到期清理，不延长有效期。队列暂停/恢复与固定审计事件在同一事务中，原生 options 必须为 InnoDB；队列操作不保留收件地址或消息正文快照。业务审批与通知记录继续使用已有事务和幂等事件；邮件失败不能触发重复审核、创建 Skill 或自动发布。

## 配置与安全预览

配置诊断只显示邮件是否启用、专用加密配置是否可用、暂停状态及 Cron 调度情况。密钥继续从服务端配置读取；后台不显示 Key、Token、验证链接、邮箱地址、登录名、租约或密文。错误只展示固定允许代码和受控说明，不输出传输异常原文。管理权限使用 `aish_manage_notifications`，每次操作检查最新账户状态、Nonce 和数据库版本，后台页面发送 no-cache/noindex。

中英文预览使用明确占位符，覆盖邮箱验证、变更邮箱、密码重置和安全通知；不从队列提取真实凭据，不调用邮件服务。

真实邮件发送测试必须有明确授权收件人。本轮测试将真实 WordPress/MySQL 队列操作与 Mock 传输分开记录；没有实际外部服务或收件授权时，真实发送和送达保持未执行。详细证据见 [PHASE_12_REPORT](PHASE_12_REPORT.md)。
