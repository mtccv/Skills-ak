# AI 内容生成安全与数据边界

Phase 6 的 AI 是辅助编辑器。GitHub 文件和模型输出都是不可信数据，不能授权系统执行命令、读密钥、访问任意 URL、操作后台或发布内容。本轮没有运行未知 Skill、安装其依赖或增加模型工具执行接口。

## 来源隔离与输出校验

Prompt 由固定 system 策略和 JSON 编码的 user 来源组成，版本为 `aish-analysis-1`。来源只保留白名单字段，人工译文/基线、凭据和后台控制字段不进入 Prompt。文件中的“忽略指令”“读取密钥”“访问某 URL”等仍是被分析文本；即使模型未遵守提示，也没有执行工具或写入正式内容的权限。

来源与模型输出分别限量，常见凭据模式脱敏。JSON 校验拒绝无效内容、重复键、类型混淆、额外字段、缺少语言、过长文本和不支持的状态。依赖/平台/风险证据必须引用来源；安装命令必须与来源中的文本一致。输出渲染时转义，人工富文本使用既有 KSES 约束。

这些控制不能证明模型理解正确：逐字引用可能被误解、恶意来源本身可能包含危险命令、常见模式脱敏可能漏掉特殊秘密，语言字符检查也不能证明翻译质量。因此结果始终待审核，风险分析没有“AI 认证安全”的含义。

Phase 7 首批审查发现原重复 JSON 键正则遇到长字符串可触发 PCRE JIT 栈限制，而未检查失败。现对已验证合法的 JSON 做线性扫描，按对象检查解码后的键，覆盖长字符串、嵌套与 Unicode 转义重复键；不会把解析器资源错误当成无重复。另将审稿历史改为元信息分页、单份快照按需读取，避免合法长草稿累积使详情页大量占用内存。以上是结构校验与资源边界修复，不代表完成真实 AI 或整站安全验收。

## Provider 与密钥

密钥只来自受保护的服务器环境/常量，后台只有固定掩码，不保存到 options 或任务。HTTP 使用受限 HTTPS Base URL、精确服务器域名白名单、公网 DNS 检查、WordPress 安全请求、TLS、超时/体积上限和零重定向；来源、输出均不能扩展主机列表。未知工具调用、被截断响应及密钥回显被拒绝。

错误只记录固定代码和数值用量，不记录 Authorization、原始错误体、SQL 或异常堆栈中的请求。模型、价格和配置快照不含密钥；发送任务前核对当前配置和 Prompt 版本，配置变更后不能悄悄切换服务。

主机白名单与安全 HTTP 机制仍需在真实部署中验证 DNS、代理和出站策略。它们不是允许选择不可信供应商的理由，也不保证识别恶意服务通过任意编码返回的凭据。不要上传未获授权的机密来源或人工私有内容。

## 人工内容保护

- AI 原始结果、人工草稿、GitHub 原文及现有译文分别存储和展示；修改人工草稿不会改写原始 AI 响应。
- 采用事务检查 Skill 修订、来源指纹、译文完整基线及 AI 草稿修订，只填选中的空标题/摘要/正文。已有字段和 slug 不被覆盖；来源/人工数据变化时拒绝旧草稿。
- 采用后设为 pending 并提高修订，仍需既有人工审核；采集/生成 worker 没有发布入口。不存在的翻译或 slug 不自动编造。
- 分类、标签、平台只是建议，AI 不创建词条或修改关联；AI 风险不覆盖静态扫描或人工风险等级。
- 权限由专用 WordPress capability 决定，nonce 仅防请求伪造，不能代替授权；非授权登录用户也不能访问管理流程。

源码中可信 PHP 扩展接口不是公开 API。数据库 DAL、Provider filter 和内部 worker 方法不应直接暴露给用户请求。

## 重复执行、恢复与费用

任务唯一请求键和每 Skill 活动任务键阻止本地重复提交；请求前建立持久尝试，再使用有界后台租约发起网络请求。租约过期时旧 worker 不能写回新状态。发送后进程中断不能证明供应商未执行，因此过期 in-flight 尝试变为结果不明，保留未知用量并阻止自动重发。

明确限流/服务错误可以退避；超时等模糊结果需人工确认重试。不能宣称跨供应商“恰好一次计费”。成本为根据配置价格与已知用量的估算；缺失 Token 或某次费用未知时总量保持未知，不能冒充零。全局/单项暂停只阻止未来请求，不假装撤销已发送请求。

## 数据保留与 Final QA

schema 1.5.0 只增加 `ai_jobs`、`ai_attempts`、`ai_reviews`；原十一张表定义保持不变。迁移继续使用锁、dbDelta、结构验证，成功才推进版本。主题停用/升级或配置移除不清理内容、任务、草稿、用量及人工记录；历史容量和备份恢复需纳入运维验收。

本轮隔离 Mock 检查不能代替以下真实验收：

- OpenAI 与选定兼容服务的认证、模型参数、JSON、用量、限流、超时、供应商计费及模型切换。
- 出站代理、DNS/IPv4/IPv6、私网拒绝、重定向、响应上限、WordPress HTTP hooks 与密钥保护。
- MySQL 1.4→1.5 及历史逐级迁移、重复升级、唯一索引、事务回滚、并发租约/入队/编辑/采集/采用竞争。
- HTTP 已发送但进程中断、数据库写回失败、超时恢复、未知费用、重试确认和暂停恢复的真实行为。
- WordPress 原生后台各角色、nonce、转义、草稿比较/采用/拒绝、已发布内容保护、来源更新和主题切换。
- 中英文质量、事实依据、安装说明、未知依赖/License、提示注入对抗、浏览器与端到端，以及 Phase 0–5 回归。

未执行的项目必须保留待测状态，不得以 PHP 语法或 Mock 通过替代真实 AI、WordPress、MySQL 验收。


## Phase 7 第二轮加固

独立请求键遇到已有活动任务时明确拒绝，避免误报幂等受理后同一表单晚到又创建付费任务；重复原键仍返回原任务。连接测试复用草稿的严格 JSON 解码、重复键、大小和类型边界，只接受精确 `{"ok":true}`。这些修复不修改正式译文或人工内容。

AI 全局 worker 锁和配置锁覆盖事务外原生查询；检测断线立即中止，不在失去连接级锁后自动重连继续。事务回滚无法确认则隔离该请求连接，未知 COMMIT/HTTP 结果不可假称撤销。已发出的请求即使数据库连接随后中断也可能计费，租约过期的 inflight 继续转 uncertain，不自动盲重发。严格模式针对受支持的 WordPress mysqli 路径，不替代实际故障和并发验收。日志继续只含固定错误码和经验证的元信息；详见 [第二轮报告](PHASE_7_ROUND_2.md)。
