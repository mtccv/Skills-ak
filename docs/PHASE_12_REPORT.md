| 范围 | 实现与边界 |
|---|---|

| 搜索隐私 | 明确用途同意、成功结果签名、同源/Nonce、有限预算、敏感词排除、同日5观察主体门槛、低频无明文及有界清理 |
| 来源健康 | 复用仓库/jobs/imports/logs，区分部分扫描、失败、限流、疑似缺失和快照处理；只有限排队既有采集，不自动删改资源或作者关系 |
| 首页运营 | 扩展原10模块的双语选择、UTC有效期、发布校验、私有修订预览、失效提醒和同事务审计；人工精选与自然排行分开 |

## 问题与修复

| 等级 | 实际问题 | 修复和回归 |
|---|---|---|
| P1 | 原生修改邮箱可能把暂停账户改为待验证，绕过运营恢复决定 | 原生邮箱更新保留暂停并撤销旧邮箱证据；人工恢复时重新核对邮箱绑定，无有效证据进入pending_email；隔离及真实WP回归 |
| P2 | 通知偏好保存重写由开发者模块保护的公开资料授权，已公开资料用户保存失败 | 在锁内核对最新授权，仅写通知偏好；禁止借通知设置变更公开同意；真实WP回归 |
| P2 | SEO由插件接管时，首页私有预览的接管时机可能遗漏Canonical抑制 | 预览明确重新执行共享SEO所有权/防索引处理，补对应隔离及实际HTTP检查；不冒充真实插件组合验收 |
| P2 | 热门场景先取Top10再过滤过期项，会漏掉后续有效场景 | 复用Discovery的公开专题SQL，在排名/限制前过滤有效期和译文 |
| P2 | 升级首次原生后台请求先执行admin_menu、后执行admin_init，新增权限注册过晚 | 权限授予在admin_menu优先级0完成，同时保留admin_init兜底；仍限定已有管理员和正常schema |
| P2 | 管理员修改邮箱后，邮件运营额外状态检查妨碍故障恢复 | 对原生manage_options管理员保留pending_email例外；暂停、删除、重复或异常元数据仍拒绝 |
| P2 | 继承的MySQL不区分重音排序规则可能合并不同合格搜索词桶 | 以稳定ASCII词标识隔离聚合键，展示时受控解码；保持低频门槛，无DDL |

另补充了仓库锁内的停用检查、快照处理CAS、邮件与Worker共享锁/可恢复条件、原生options事务引擎检查、提交后缓存失效，以及Dashboard计数与链接筛选一致性。测试过程中的桩函数缺失、模板样本及容器挂载旧inode问题已明确排查；未用这些中间结果宣称最终通过。

## 未执行与已知限制

1. 外部SMTP/真实邮件送达：没有本轮明确授权收件人或真实邮件传输配置。不能报告送达或送达率。
2. WPML：无合法插件测试环境，保留接口但本轮真实联调未执行。
3. GitHub真实API：本轮不使用应用凭据调用外部仓库，原安全客户端/调度Mock回归与本地队列测试分开。
4. AI真实API：无本轮真实Provider配置和费用授权，不调用付费API或自动恢复任务。
5. 第三方SEO插件组合：本轮测试共享SEO合同、Hook边界及HTML；不能替代实际Yoast/RankMath插件组合验收。
6. 第三方持久对象缓存、全页缓存/CDN：未搭建真实组合。必须遵守私有no-store、Nonce/证明有效期和内容清除策略。
7. 生产规模/持续压力、完整多站点和其他浏览器引擎：没有相应生产等效环境。本轮有限并发和QA计时不能外推容量。

运营Dashboard在当前小样本里有193–195次SQL读取，属于复用域服务及权限检查的固定开销；尚未针对大型业务库优化计数投影。详见 [性能实测](../PERFORMANCE_REPORT.md)，不将局部计时外推为生产容量。

分析为有同意、有覆盖的观测，不代表所有访问或全部真实独立人；不推算历史、不过度承诺反机器人。低频抑制、词数上限和安全文本规则会降低覆盖；场景/分类热度是成员Skill浏览累计。投稿时长只基于仍保留的可配对事件。Cron故障可能延后物理清理，恢复后分批追赶。
