# GitHub Skills 采集使用说明

Phase 5 在现有 Core 内增加 `sources` 模块，使用 WordPress Cron。无需 Action Scheduler，不运行外部采集服务。采集仅支持公开 GitHub 仓库，所有新增 Skill 都是待审核记录，不能自动发布。

## 配置与入口

1. 更新主题后，由有权限的管理员访问后台，让既有迁移器执行 schema **1.4.0**。迁移不在普通前台请求执行；失败时采集保持不可用，不虚报升级成功。
2. 打开 **AI Skills Hub → GitHub Imports**。需要 `aish_manage_repositories` 或 `manage_options`；处理来源变更还需要 `aish_review_skills`。原有 Skills / Reviews 页面继续负责内容编辑和人工审核。
3. 添加 `https://github.com/owner/repository`，可带 `.git`。不接受任意主机、SSH、凭据、端口、查询或片段。保存只登记配置，不在后台页面请求中访问 GitHub。
4. 定期同步默认关闭；可配置 3600–604800 秒间隔，默认 86400 秒。批量扫描、同步或关闭定期同步最多选择 10 个仓库。

Token 可选。需要时通过服务器环境变量 `AISH_GITHUB_TOKEN` 配置，也可由受保护的 WordPress 配置定义同名常量（常量优先）。现有 Cloud Compose 已传递该环境变量，`.env.example` 仅含空项。实际值只能写入不受 Git 跟踪的秘密配置，不应放入主题、页面、截图、日志或仓库。后台仅显示“已配置/未配置”和最近限流状态，不提供读取 Token 的接口。没有 Token 时仍可使用公开 API；有 Token 也不采集私有仓库。

## 扫描与增量同步

**完整扫描**重新检查目录和所有候选文件。**增量同步**先比较默认分支 Commit：与最后成功基线相同、仓库 License 未变化，且前一个仓库任务也完整成功时，才复用该完整基线并明确显示“Commit 未变化”；否则重新取得固定 Commit 对应的目录树。失败或取消任务可能已保存部分来源，因此即使上游回退到旧 Commit，也必须重新核对。文件 SHA 相同可复用已有原文，但仍会重新检查当前树中的依赖、脚本等元数据。原文缺失或校验失败时重新读取 Blob。

任务依次执行仓库信息、Commit、Tree、逐个文件、最终清单对账。每次 Cron 只推进一个阶段或一个文件，阶段之间至少间隔 60 秒。Git Tree、Blob 均使用固定 SHA，不混用运行期间移动的默认分支。远程步骤核对 GitHub Repository ID，遇到仓库改名、替换或不可公开访问时停止本次任务，不自动跟随重定向或改绑来源。

只发现精确命名的 `SKILL.md` 普通文件，支持根目录及多个子目录。递归 Tree `truncated` 或响应体超限时，丢弃部分清单并从固定根 Tree 按目录继续扫描。非递归 Tree 仍截断、树结构异常或超限时标记不完整。解析某个文件失败会记录固定错误代码并继续其他候选，但整个任务不能标为完整。

只有完整目录、所有候选处理成功、零错误且最终清单已持久化对账，才更新 `last_sync_at` / `last_sync_commit` 及对应的 `license_spdx` 基线。部分成功的新来源可以进入待审核后台；失败任务不推进完整同步基线，也不推断旧来源已删除。License 仅在完整成功时推进，防止中断后误跳过许可证变化检查。

Phase 7 首批加固保留已经提交的清单对账标记及缺失计数：最终收尾写入失败后，重试或旧检查点不能用旧内存状态覆盖该结果，也不能更换对应 Commit。最终失败仍显示真实失败状态；只有完整收尾才推进仓库成功基线。原生 Repositories 和 GitHub Imports 两个入口现在共用归档逻辑，同时关闭同步、取消活动任务并撤销租约；恢复仓库不会复活这些已取消任务。

## 来源、版本与人工处理

- 身份使用现有 `repository_id + source_path` 唯一键，不按 Skill 名称去重。相同路径反复采集保留 Skill ID；一个仓库可以包含多个 Skills。新增项固定 `pending` / `review_status=pending`，没有自动生成的中文或英文翻译。
- File SHA 变化时追加不可变版本，保存 Commit SHA、File SHA、内容散列和来源路径快照。不会覆盖人工翻译、已发布 slug、审核修订或发布状态。来源快照属于待处理证据，不能代表已审核的新公开版本。
- 同一 Blob 的目录风险发生变化时标记 `inspection_updated`。来源 Commit 指向原文快照；风险结果的 `inspection_commit_sha` 指向本次检查的目录 Commit，两者可能不同。
- 完整扫描发现旧路径消失时标记 `missing`，保留 Skill、译文、公开页面及历史版本。恢复原路径标记 `restored`。新路径与消失路径的 File SHA 相同会记录 `possible_move`，由管理员核实；不按猜测自动合并或变更稳定 ID。
- “来源变更”页可筛选新增、更新、风险变化、缺失、恢复及已处理记录，查看原文、路径、SHA、License 和检查结果，再跳转原生 Skills / Reviews 编辑和审核。原文按文本转义展示，不执行 Markdown 中的 HTML 或脚本。
- 管理员补充真实中文和英文内容后按原有审核流程批准、拒绝或归档。标记“来源变更已处理”只确认通知，不发布 Skill。确认携带来源指纹；记录已经变化时必须重新载入后确认。
- “关闭定期同步”不取消已排队的手动任务。需要停止该仓库全部采集时使用“归档并停用”，经确认后撤销任务租约；保留全部业务数据和日志。显式编辑保存归档仓库可恢复仓库记录，界面会提示这一行为。

## 调度与状态

后台注册 `aish_import_tick` 每分钟事件；WordPress Cron 依赖站点流量或现有 Cloud 中的受控 Cron 触发，低流量时会延迟，配置间隔不是准点承诺。禁用 WP-Cron 或无法触发时任务只会排队，不能视作采集成功。普通前台请求只注册模块，不执行扫描。主题停用清除采集 Cron，保留任务及来源数据；重新启用并完成后台检查后可恢复。

每个仓库只允许一个活动任务；重复提交返回已有任务。新任务至少间隔 60 秒，定时调度每轮最多考虑 20 个仓库。调度器持有全局 worker 锁，每轮执行一个步骤；存储层另限制最多两个有效租约以保护其他可信后台调用。租约 120 秒，过期可恢复；任务总截止时间 48 小时。连续失败最多 5 次，成功保存检查点后重置连续失败次数。限流和临时网络/5xx 错误使用延迟任务与退避，不在 PHP 进程内长时间 sleep。

| 状态 | 含义与处理 |
| --- | --- |
| queued / running | 已排队 / 正在执行一个小步骤，不表示完整扫描 |
| retry | 等待限流冷却或临时故障退避；查看可执行时间 |
| complete | 完整处理成功，或明确复用未变化的完整 Commit 基线 |
| incomplete | 目录或文件处理存在问题；查看错误代码，修正后重新扫描 |
| failed | 连续失败或任务截止时间已到；修正原因后重新入队 |
| cancelled | 仓库停用/归档，保留历史任务记录 |

后台 API 状态来自最近请求缓存，不会为了查看页面而请求 GitHub。认证失败应修正服务器配置；限流按 API 的 reset / Retry-After 冷却。仓库或文件不可访问时不尝试匿名绕过或任意下载地址。日志只记录受控事件代码、路径、关联 ID 和时间，最多 1000 条去重事件/任务。

## 有界资源与格式

| 项目 | 当前上限 |
| --- | --- |
| HTTP | 每次 15 秒，禁止重定向，TLS 校验，固定 `api.github.com` |
| Tree 响应 / 发现状态 / 任务状态 | 4 MiB / 2 MiB / 4 MiB |
| 目录清单 / Skills / 深度 / Tree 请求 | 10000 项 / 500 个 / 32 层 / 1000 次 |
| SKILL.md / Frontmatter | 512 KiB / 16 KiB、256 行 |
| name / description / compatibility | 64 ASCII 字符 / 1024 字符 / 500 字符 |

Frontmatter 使用受限 YAML 子集：标量字符串、引号、字面/折叠块及一层字符串 `metadata` 映射。允许 `name`、`description`、`license`、`compatibility`、`metadata`、`allowed-tools`；拒绝未知字段、重复键、非字符串类型、对象标签、锚点、别名、合并键、复杂集合和不支持的语法。`name` 必填且符合标准命名规则，嵌套 Skill 与父目录名匹配；根目录 Skill 记录结构提示。拒绝原因进入日志，不静默改写不可信原文。

这些限制是本阶段的保守实现边界。超限不能绕过验证或假装完整，可拆分来源仓库或经后续明确设计调整限制。风险检查只检查 SKILL 文本和树元数据，不读取所有脚本内容；License 未知标记待核实，详见 [采集安全说明](IMPORT_SECURITY.md)。

## 验证范围

本阶段执行 PHP 语法、前端构建和隔离模拟测试。真实 GitHub API、WordPress Cron、MySQL 迁移/事务锁/并发、后台浏览器操作及完整端到端均留 Final QA。模拟响应通过不代表 GitHub 网络环境或完整 WordPress 运行已验收。详见 [Phase 5 报告](PHASE_5_REPORT.md)。


## Phase 7 第二轮的兼容与恢复

旧 Phase 1 版本缺少 File SHA/repository/path 时，不允许直接成为 AI 来源。增量同步只有在当前 present 来源都能关联完整版本身份时才复用同 HEAD 的完成基线；发现缺失绑定则走正常固定 SHA 的树/Blob 扫描。也可手动使用完整 Scan。只补齐本次确实核验的同 Commit、同原文版本中的空身份字段，不修改历史原文、ID、时间、标签或已知身份；其他历史 Commit 不被猜测回填，冲突保留失败待处理。

检查点将任务和仓库同时更新为 queued；第五次连续失去租约立即终止并释放活动键，不额外执行第六次。成功步骤仍重置连续失败计数。全局 worker 锁的完整作用域阻止 wpdb 在断连后自动重连继续；已经发送的 HTTP 无法撤销，租约和 fencing 仍承担恢复/过期写入保护。真实限流、进程中断和并发验收仍留 Final QA，证据见 [第二轮报告](PHASE_7_ROUND_2.md)。
