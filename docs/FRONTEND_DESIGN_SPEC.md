## 1. 设计目标与现状边界

用户应在首页理解平台用途，在列表缩小选择，在详情判断适用性、来源和限制，再按实际已开放能力收藏、评价、学习或投稿。资源阅读优先于注册；注册不是访问公开内容的前提。当前免费运营，不出现付费墙、结账或虚构会员权益。

## 2. 视觉基础与响应式系统

完整定义以 [DESIGN_SYSTEM](DESIGN_SYSTEM.md) 为单一来源；以下为前台常用子集。

| shadow | `0 8px 24px #1118270A` | 弹层和重点卡片；普通列表以边框为主 |

字体使用本机已有 Inter、ui-sans-serif、system-ui、系统中英文字体栈，代码使用系统等宽栈，不依赖外部字体 CDN。中文正文16px / 1.8–2，英文16px / 1.65–1.85，辅助字最小12px、必要表单说明14px。Hero为Desktop56 / Tablet48 / Mobile36px，页面H1为42 / 30–32px，区块H2为30 / 24px，卡片H3为18px。长标题自然换行；正文约65–75字符行宽，代码块局部横滚。

### 2.2 布局 / layout

- Desktop：`>=1024px`。无侧栏标准列表 3 列；Skills 列表左侧 240 px 筛选、间隔 24 px，视口 1024–1279 px 主区 2 列，>=1280 px 主区 3 列；详情主列与 320 px 资料栏，间隔 32 px。桌面导航单行，不挤压语言和账户操作。
- Tablet：`768–1023px`。卡片 2 列，筛选进入 native details 内联展开面板，详情主要来源动作前置，完整资料栏落在正文后；主导航折叠。保持触控与键盘，不把“悬停可见”当唯一入口。
- Mobile：`<768px`。单列资源卡片及分类入口、16 px 边距、区块上下 40–48 px；Hero 搜索占满一行，按钮可另起一行；侧栏重排成行内区块。320/360 px 宽可完成关键操作，不要求整页横向拖动。
- 1920 px 大屏继续使用 1280 px 容器，不无限拉长行文；200% 缩放允许导航折叠，400% 下仍可按单列阅读。表格/代码等确需横向滚动的局部区域有标签和可见滚动提示。

### 2.3 组件 / components

| 组件 | 外观与结构 | 交互、信息边界 |
| --- | --- | --- |
| Button | 主/次/文本/危险四种；图标与文字间距 8 px | 默认、hover、focus-visible、pending、disabled；pending 保留宽度和可读文字；链接导航不伪装提交 |
| Card | 图标、标题、简介、最多 2 分类 + 2 平台、事实/行动栏 | 标题为主要链接；收藏等独立按钮不嵌套在整卡链接内；省略简介不省略可访问名称 |
| Badge | 中性、精选、已审核、赞助、状态 | “内容已审核”带解释入口；不出现“绝对安全/官方认证”；赞助始终明示 |
| Search | 可见或 sr-only label、关键词、提交、可选快捷提示 | GET 可用；空词可进入目录；不暗示自然语言 AI 搜索已实现 |
| Filter | 原生 select/checkbox、已选 chips、清除 | 后台只提供已有字段；选择与提交分开，手机“应用筛选”明确生效 |
| Pagination | 上/下一页、当前页、有限页码 | 真实链接保留有效筛选；点击回到结果标题；不用无限滚动替代基本访问 |
| Status panel | 图标、标题、解释、单个主要恢复行动 | 空、未开放、无权限、出错、待处理分别用词；未知值不显示为 0 |
| Form field | 标签、必填说明、输入、帮助、行内错误 | 错误关联 `aria-describedby`；首错摘要可跳字段；不只靠红框 |
| Tabs / disclosure | 下划线/实底选中；有明确名称 | 详情长内容优先锚点目录；真 tabs 才用 tab 语义及键盘，不用 tabs 隐藏全部 SSR 内容 |
| Toast | 非阻断简短结果 | `role=status`；失败在相关区域持久显示，不只留短暂 toast |
| Dialog / drawer | 标题、关闭、操作区 | Escape、焦点进入/约束/返回、背景不可误操作；无 JS 提供普通页/原生 disclosure |

### 2.4 状态 / states

首次 SSR 正常时直接显示内容；只在真实异步交互发生后显示加载状态，不故意添加 skeleton 延迟。局部加载使用 `aria-busy` 和简短状态文字，屏幕阅读器不反复播报整个列表。数据为空、无搜索匹配、功能未开放、读取失败、权限不足和资源已撤下必须分别表达。

动画只用于 120–180 ms 的颜色、边框、轻微面板过渡，不让卡片大幅跳动。尊重 `prefers-reduced-motion`；导航、弹层和反馈不用动画结束作为业务完成依据。

### 2.5 验收 / acceptance

正文目标对比度至少 4.5:1，大文字至少 3:1；控件边界/焦点至少 3:1。键盘按视觉阅读顺序完成导航、筛选、分页和表单，焦点始终可见；图标按钮有中文/英文名称。360/768/1024/1440 px 与长中英文标题下，关键内容不遮挡、不截断操作、无整页横向溢出。实际对比度和读屏结果须后续测量，设计值不是通过证明。

## 3. 全站公共壳层

**布局：** 页首 72–80 px：品牌 → 主导航 → 语言 → 账户/投稿。主导航按“发现 Skills / Explore”“教程 / Learn”“精选 / Collections”组织；集合尚未开放前只呈现已实现入口。About、Contact、帮助和规范在页脚，不让一级导航超过可读宽度。首页品牌链接指当前语言首页；详情/列表以面包屑提供返回上下文。

**组件：** skip link、brand、主导航、当前页状态、语言切换、访客登录/注册或账户菜单、移动菜单、页脚三组链接。主行动依页面而变：首页搜索，列表筛选，详情来源/收藏，投稿保存提交。页脚显示真实说明、政策/联系链接及当前年份，不放虚构用户数量、客户 Logo 或“所有资源已认证”。

**状态：** P8 前账户入口不出现可操作假按钮；后续未登录显示登录/注册，已登录显示本人头像/名称及用户中心。未验证账户显式提示验证状态，不能仅凭头像判定可互动。页面缺译时语言动作转到目标语言对应列表并提示“此内容暂未提供该语言”；实体的“可用语言”只列真正可公开版本。不要把通用导航语言 fallback 标成该实体的 hreflang 关系。

**移动：** 品牌、语言、菜单保持一行；登录/投稿放展开导航内。菜单可用原生 details 作基础，增强时补焦点返回与 Escape。sticky header 如实施不得遮住锚点、错误提示或 44 px 操作区域；手机不额外加拥挤的全站底部导航。

**验收：** 每页只有一个 main 和一个主 H1，语言切换后站内链接一致；菜单关闭后焦点返回触发按钮；导航不会把未开发功能导向 404；页脚和页面 chrome 在中英与错误页都有完整界面译文。

## 4. 公开页面设计

### 4.1 首页 `/{lang}/`

**布局：** 顶部浅色 Hero，左/中对齐价值文案与大型搜索，右侧可放小型精选资源展示；不让装饰压过首屏搜索。其后推荐顺序为分类/平台捷径 → 趋势资源 → 编辑精选 → 最近内容更新 → 高评分 → 教程 → 投稿或自愿订阅行动。首版只启用已具备真实服务的模块，趋势/评分等依赖未就绪时不出现空的“成功排行”。完整模块合同见第 5 节。

**组件：** Hero、独立 search、最多 8 个分类/平台入口、区块标题+解释+查看全部、ResourceCard、紧凑 RankRow、TutorialCard、轻量贡献 CTA。Hero 装饰用原创抽象节点/资源文档，不嵌入终端执行假命令。Hero 与 search 是不同模块，视觉可以同区呈现，运营可以分别管理。

**状态：** 无目录内容时保留搜索、用途介绍和投稿/教程入口；精选为空提示“编辑正在整理精选”；真实排行数据不足显示“数据积累中”及起始时间或按配置隐藏；读取失败不能改写为 0 资源。局部可选模块故障只显示该模块受控不可用；共用语言/索引策略失败仍遵守整页 503，不能降级泄露旧内容。

**移动：** Hero 取消右侧装饰或移到文案后；搜索 100% 宽；资源卡和分类单列；分类桌面 4 列、平板 2 列；不依赖横滑才能发现全部核心入口。榜单行保留排名、标题、指标，次要标签可减少。

**验收：** 关闭/排序模块只改变结构，不改变其他模块 source；切换语言不混入另一语言资源；资源撤稿后所有首页位置在下一次公开请求消失；没有足够评价时无虚构高分榜；首屏可以完成搜索，页面仍有且只有一个 H1。

### 4.2 Skills 列表、搜索、分类、标签与平台入口

路由沿用 `/skills/`、`/search/?q=…`、`/category/{slug}/`、`/tag/{slug}/`；平台当前是 `/skills/?platform=platform-*`，独立平台落地页需 P11 另行路由评审，原链接保持兼容。

**布局：** 面包屑/标题/简短说明 → 搜索 → desktop 左侧筛选或顶部紧凑筛选 → 结果数/当前排序 → 网格 → 分页。分类/标签使用真实名称；没有真实介绍不复制通用 SEO 内容充当编辑文章。搜索页上方回显安全转义后的关键词，展示 Skills 结果与最多 3 条教程预览及“全部教程结果”链接。

**组件：** 搜索框、分类/标签/平台筛选、排序 select、已选 chips、reset、结果摘要、ResourceCard、分页、教程结果区。沿用当前长度上限 100 Unicode 字符/400 UTF-8 字节、每页 12、API 最大 24、page 上限 10000；图形筛选不扩大这些上限。当前排序显示“更新时间：最新/最早”“标题”，避免暗示 P11 的经审核公共更新时间。排名类排序在 P11 实现前不接受或展示。

**状态：** 正常结果、无匹配、空目录、正在提交、格式错误/无效筛选、读取失败、无效越界分页分别处理。无匹配显示当前条件和清除筛选，不偷偷改为其他语言或放精选结果冒充匹配。不存在 slug、无效参数、越界空分页保持现有 404；有效条件零匹配是可恢复空状态。浏览器后退恢复搜索字段和可提交按钮。

**移动：** native details 筛选入口显示已选项数量，打开内联可展开区域；“应用”“重置”在底部且可触达，关闭保留未提交输入并明确未应用。原型不使用遮罩抽屉；未来若改为 drawer，须独立完成焦点约束/返回与无 JS 降级验收。结果摘要与排序可换两行；分页上下页各有 44 px 点击范围。

**验收：** q/category/tag/platform 为同一 Skill 的 AND 条件，教程筛选遵守关联公开 Skill 规则；应用筛选/换语言回第 1 页；分页保留条件；selected slug 超过选项前 200 项时仍可见不被丢弃。搜索/筛选/显式排序 noindex，正常纯 page 分页自引用 Canonical。

### 4.3 Skill 详情 `/{lang}/skills/{id}/{slug}/`

**布局：** 面包屑 → 标题/简介/真实平台/审核说明 → 行动区 → 内容主栏和来源资料侧栏。主栏顺序为概览、使用场景、安装与依赖、使用限制/风险、公开评价、相关 Skills、相关教程；旁栏为来源仓库/文件、维护者、真实作者归属（P10）、许可证、历史版本与语言。长内容提供锚点目录，正文仍服务器完整输出，不将 SEO 内容藏在只有 JS 能载入的 tabs 中。

**组件：** 标题头、来源 CTA、收藏（P9）、评分摘要（P9）、分享（P14）、事实 dl、风险面板、安装代码块、目录、评价列表/表单入口、相关卡片。来源按钮文案“查看 GitHub 来源”，人工来源显示实际信息；不是“立即安装”。正文提取出的场景/安装/依赖采用同一份已审内容，后续重排避免把完整正文与提取章节重复渲染两遍；标题提取失败时保留完整正文和缺失说明。

**状态：** 作者未提供、许可证未提供、未标注平台、无可核实命令、暂无评分、来源状态待核实各自显示。风险 unknown 与 low/medium/high 都有文字解释；内容审核不等于运行安全保证。现有历史 SHA 说明“记录的来源版本，未与当前审核正文建立可验证绑定”；`version_source_verified=false` 时不使用该 SHA 拼接“安全安装”操作。来源 HEAD 链接不能标为固定审核版本。

已下线、审核失效时不显示旧标题/正文或收藏快照，返回现有 404。直接访问缺少当前语言的详情，若同一 Skill 有真实可公开的另一译文，保留现有 302 到实际译文并显示缺译提示；完全无可公开译文才 404。此重定向不生成缺失语言 Canonical/hreflang。P9 评价首次 pending 不公开不计分，已公开评价编辑时旧批准版本继续展示，作者本人另见“修改待审”；其他访客不可见新稿。P10 认领仅显示经批准的角色，不把 repo owner、提交者或审核员当原创作者。

**移动：** 标题和行动允许换行；来源概要置于正文前，详细资料可 disclosure；目录变为“本页内容”；收藏与来源最多两项一行。代码块局部滚动，长 source_path/SHA 可断行；移动底部行动若采用 sticky，须预留等高空间和安全区，不能遮住评价/页脚。

**验收：** 至少覆盖人工来源、GitHub 来源、单语、缺作者/License/平台、无安装段、无评价、评价编辑待审、来源版本未知、撤稿等样例；同 Skill 的中英收藏和评分为同一主体。分享只取当前语言公开 Canonical；命令只复制可见完整文本、有来源依据、用户主动触发，不执行、不下载依赖、不猜命令。复制失败保留可选中文本和说明。

### 4.4 榜单与发现页（P11）

包括 `/trending/`、`/most-viewed/`、`/most-favorited/`、`/top-rated/`、`/recently-added/`、`/recently-updated/`、`/editors-picks/`。

**布局：** 榜单标题/真正统计说明 → 时间窗/数据更新时间 → 分类/平台等过滤 → 排名行或卡片 → 分页 → 口径说明。Trending 可以带紧凑趋势视觉，但只有真实历史点才画曲线；无历史不生成装饰数据图。编辑精选不显示自然排名上升/下降徽标。

**组件：** RankRow、MetricLabel、WindowSelector、方法说明、空状态、分页。Trending 使用路线图的版本化公式及 7 个完整 UTC 日；Most Viewed 标“日去重浏览累计”，不称周期独立访客；Most Favorited 是当前有效收藏；Top Rated 显示均分与有效人数，建议至少 5 个评价入榜；Recently Added 标“最近收录”；Recently Updated 来自 P9 工作流的真实公开内容批准事件。排序最终用稳定 ID 打破同分。

**状态：** 有数据、数据尚不足、收集起点不足一个窗口、聚合更新中、上次成功数据、不可用分别呈现。旧聚合可用于说明上次成功时间，但仍需实时公开门禁；无法证明评分/收藏有效性时暂停对应排名，不拿错误空结果当 0。

**移动：** 每行两层：排名/标题/收藏，其下指标/平台；不保留多列桌面表头造成横向溢出。方法说明可折叠，当前统计窗口始终可见。

**验收：** 固定样本可复算、并列稳定、撤回评价/取消收藏/下线立即影响下一次公开结果。无信号的 Skill 不进入 Trending，少于门槛不进高分榜，赞助不改变自然得分。固定真实内容入口按 SEO 规则可索引，窗口/排序/筛选参数 noindex。

### 4.5 集合、场景与开发者公开页（P10–11）

**布局：** 集合/场景目录用内容卡片，详情用标题、真实简介、适用范围、维护信息和有序 Skills；开发者页用经审核公开资料头部、角色说明、真实关联资源，避免社交关注流。语言前缀后集合路由 `/collections/{id}/{slug}/`，场景 `/use-cases/{id}/{slug}/`，开发者 `/authors/{public_handle}/`；handle 不使用邮箱或内部登录名，统一由 Router 注册。

**组件：** CollectionCard、场景导航、ProfileHeader、RoleBadge、ResourceCard、相关教程、分页。集合稳定 ID 中英共用；成员引用原 Skill ID。平台集合复用 `platform-*`，精选来源复用 `featured`；开发者关系区分作者/维护者，不以“验证”概括所有可信度。

**状态：** 未发布/撤回公开资料、没有真实译文、空集合/暂无关联资源、认领待审/撤销、原共享分类名缺译。公开页不展示认领证据、邮箱、投稿草稿或运营备注；争议处理不暴露举报人。

**移动：** 简介单列，头像与名称同行或上下；关联卡片单列，长用户名/网站能换行；集合排序序号不挤压标题。

**验收：** 新页面不能查询管理 Catalog 直接列资源；成员撤下即隐藏，真实公开资源数同步减少；开发者资料需用户主动公开及审核，撤销后无旧快照泄漏；缺译不复制他语正文或生成 hreflang，空集合不进 Sitemap。

### 4.6 教程列表与详情

**布局：** 列表沿用筛选结果结构，卡片用原创轻量插图/真实封面、标题、摘要、作者/更新时间。详情最大阅读宽度 800 px，标题/概要/真实作者与时间 → 目录 → 正文 → 相关 Skill → 返回列表；双栏只在目录确有价值时启用。

**组件：** TutorialCard、原生正文、目录、图片 caption、代码块、提示框、关联资源。现有教程 `aish_tutorial` 不另建教学内容库；真实作者取 WP 显示名。未提供时不猜阅读时长、难度、平台测试结论或“官方教程”。可选预计时长须有明确计算/编辑来源。

**状态：** 空列表、无筛选匹配、缺译、内容不存在/撤稿、图像不可用、关联 Skill 已撤下。教程正文仍可阅读，不因某个关联资源不可用而泄露该资源旧信息；缺图用装饰占位，不伪称实际截图。

**移动：** 正文 16 px，代码/表格局部滚动；目录 disclosure；图片宽度不溢出，长英文 URL 断行；不把段落堆成水平滑动卡片。

**验收：** 复用已有语言配对双向校验与 publish/无密码/非空门禁；教程搜索只匹配教程自身，关联筛选按现有共同 Skill 条件；目录与标题层级一致；无 JS 可读全文。详情与列表 SEO、真实 hreflang 和相关资源撤回均回归。

### 4.7 About、Contact、投稿与规范说明

**布局：** About 以清楚的目的、选录方式、来源/审核限制和联系入口为主，正文阅读宽度 800 px。Contact 为说明主列 + 表单；投稿为步骤说明/真实状态 + 来源信息/说明表单；不把一般联系和投稿混为一个状态流。

**组件：** 原生 page 正文、字段帮助、错误摘要、提交/返回、持久结果面板。当前 Contact/Submit 字段与私有 Inbox 保持兼容；P10 再将 Submit 扩展为已验证账户的私有草稿/提交/补充/接受/拒绝/撤回流程，具体字段与本人记录由用户中心设计承接。GitHub 仓库根 URL 与 source_path 分开，未知路径可明确“待确认”，不自动填 `SKILL.md`。

**状态：** 初始、提交中、字段错误、限频、成功保存私有记录、保存失败、需登录/验证（P10）、修订冲突。当前提交成功只称“已收到，等待处理”，不称“已发邮件/已收录/已发布”；接受提案与 Skill 发布分开。缺少 About/Contact 真实正文时显示功能说明并 noindex，不编造机构介绍、联系方式或政策承诺。

**移动：** 全部单列，长说明在字段下，键盘类型随 email/url 设置；提交按钮全宽。错误摘要滚入视野但不删除已输入安全内容；成功后不重复提交。

**验收：** 无 JS 通过 POST/PRG 可提交；失败不假成功、重复点击不假多次成功；Contact 保持匿名联系和私有处理，不把历史邮箱自动绑定新账户；P8 不提前改变旧 Submit 权限。输入信息不进入公开 HTML/搜索/Sitemap/日志或分享链接。

### 4.8 登录注册与用户中心的公开衔接（P8–10）

**布局：** 登录/注册/找回使用 440–480 px 单列面板，公共品牌壳层简化，提供返回浏览；用户中心用相同 tokens 和公开导航，详细导航/表格/表单以用户中心设计为准。登录返回地址限站内、当前语言，返回收藏/评价意图时由用户明确完成，不自动代操作。

**组件：** 邮箱、密码、强度说明、验证状态、通用错误、重发冷却与会话到期面板；P8 Dashboard 只显示已交付账户功能，尚未交付的收藏/投稿不呈现虚构统计或按钮。

**状态：** 访客、未验证、已验证、受限账户、会话过期、发送 queued/accepted/failed/uncertain 分开。`accepted` 仅“邮件已交给发送服务”，不称收件箱送达。匿名提示不泄露邮箱是否存在。

**移动：** 输入至少 16 px，操作 44 px，无横向滚动；密码显示按钮有读屏名称；验证码/验证链接结果不依赖弹窗。语言切换不能把敏感 token 放入新公开 URL。

**验收：** WordPress Users 为唯一账户主体，同一用户切语言不新建身份；认证页、全部个人页、验证/重置结果 noindex/nofollow/noarchive、private/no-store、不进 Sitemap；收藏/评分跨语言引用同 Skill ID。产品页面不显示 Phase 编号或技术数据库细节。

### 4.9 帮助、分享、订阅与商业说明（P13–14）

**布局：** `/help/`、`/guidelines/`、`/getting-started/` 使用帮助导航+可读正文；`/newsletter/` 说明频率、语言和可退出方式；`/sponsors/`、`/original-skills/`、`/bundles/`、`/enterprise/` 使用真实说明+集合/联系行动。功能未实现前不放可操作公开导航。

**组件：** 帮助主题卡、FAQ disclosure、教程卡、复制/分享反馈、独立未勾选 opt-in、退订结果、Sponsored 标识、私有企业联系表单。不做无真实素材的 Logo 墙/客户证明，不放“升级”“购买”或订单流程。

**状态：** 没有安装证据时不提供猜测命令；分享 API 不可用时可复制规范链接；无营销同意、待确认、已订阅、退订、过期、发送不可用分别呈现。退订不影响账户或安全邮件；赞助到期/资源撤下即不展示。

**移动：** 分享优先用户主动系统分享并保留复制；帮助导航可折叠；退订按钮易触达，无强制登录步骤；订阅说明先于确认按钮。

**验收：** 注册默认不勾选营销；无需同意营销即可继续免费使用；命令可见完整文本且不执行；分享不含用户/预览/token 参数。确认/退订结果 noindex/no-store，赞助链接适当 `rel=sponsored`，不影响自然排名/审核/评分。

### 4.10 404、503 与可恢复错误

**布局：** 保留可用的同语言公共壳层，居中小型状态插图/状态码、清晰标题、解释、单个主要恢复入口；404 提供搜索/目录/首页；503 提供刷新与稍后重试，不显示猜测的失败原因。

**组件：** ErrorPanel、重试、同语言导航；错误页不含实体内容、canonical、hreflang 或结构化实体数据。输入错误尽量在原表单呈现，不能把全部失败都导向 404。

**状态：** 404“未找到此内容”；503“暂时无法加载”；权限不足/会话过期进入对应受限流程；没有资源是列表空状态，不是服务器故障。语言/SEO adapter 故障沿用现有受控 503，不回显异常、SQL 或凭据。

**移动：** 主要行动全宽或双行，错误说明可换行；不让插图占满首屏。所有状态在无 JS 下可读。

**验收：** HTTP 状态真实，404/503 均 noindex 且无 Canonical/hreflang；503 保持 no-store/合适的重试策略，错误页面不把上次请求实体残留到界面。截图视觉通过不能代替 HTTP 验证。

## 5. 首页可扩展结构与运营合同

### 5.1 分层：视觉与内容配置分离

未来的首页结构由三层组成，全部沿用既有 Core，而不是页面构建器：

1. **共享数据层：** PublicCatalog/Editorial；P11 Discovery 仅提供候选 ID、真实指标及排序，再经 PublicCatalog 批量公开过滤。语言和 SEO 继续用当前服务。
2. **运营配置层：** 选择已开发模块、显隐、顺序、白名单 source、有限数量/资源 ID、本语言文案和有效期。配置不保存另一份 Skill 标题/正文/评分/来源，不接受 SQL、PHP、任意 HTML/JS/CSS、外部数据 URL 或模板路径。
3. **风格层：** registry 指向经开发和验证的 renderer 与 token 集；只改变视觉，不拥有发布、搜索、语言、SEO、统计或审核逻辑。

全站共享 `style_id` 保持品牌一致；中英文运营内容、模块启停和顺序分别配置。共享风格变更必须将中英一起预览、冻结并发布；不复制数据库内容以适应风格。后续允许按语言不同风格属于另行评审的产品选项，首版不启用。

### 5.2 Style registry

| 字段 | 设计合同 |
| --- | --- |
| `style_id` | 稳定白名单 ID；本轮只有 **`modern-saas`** 已设计，没有可切换的第二套成品风格 |
| 展示名称/说明 | 双语名称、缩略图、开发/可用状态；未开发项目只能在设计说明中出现，不作可选项 |
| renderer / version | 由开发者注册的模板映射与版本，运营不可输入文件路径/类名 |
| tokens / capabilities | 已验证 token 集、支持的模块和布局；不允许运营粘贴任意 CSS |
| defaults | 默认模块位置与视觉 variant；默认值不能覆盖运营正文或绕过公开状态 |
| compatibility | 配置 schema 版本、模块支持列表、可访问性/响应式验证记录；缺 renderer 不可发布 |

将来增加另一风格时必须复用相同 page context、查询与 SEO 输出；先实现全部必要模块状态和中英移动布局，加入 registry 并通过回归后才允许后台选择。“一键切换”是选择已安装风格并预览发布，不是动态生成代码。

### 5.3 独立模块与有界 source

推荐每页最多 16 个模块实例，同一模块最多 2 个实例；Hero、search 各最多 1 个，至少保留一个可见 H1/主搜索入口。每个模块含稳定 `instance_id`、`type`、`enabled`、`position`、允许的 `variant`、`source`、`limit` 和本语言标题/描述/CTA。不能仅保存数组下标作为模块身份；移动/显隐不改变 ID。

| module type | source 白名单与数量建议 | 内容/展示规则 | 依赖 |
| --- | --- | --- | --- |
| `hero` | `localized_editorial`，1 | 标题/描述/可选站内 CTA；只有一个主 H1；装饰不是真实资源证据 | 后续视觉实施 |
| `search` | `public_search`，1 | 默认去综合 `/search/`；复用同一参数规范化/语言；scope 只能选已实现入口 | 既有查询，接线待实施 |
| `categories` | `public_categories`，4/8/12 | 当前语言有公开资源的原分类；计数真实；缺名称译文按第 6 节 | 既有；真分类译文 P11 |
| `platforms` | `verified_platform_tags`，4/8/12 | `platform-*` 人工标签，不能凭运营文案声称兼容 | 既有 |
| `editors_picks` | `featured_tag` 或 `featured_selection`，3/6/9/12 | `featured_selection` 只是从已关联 featured 的公开资源挑选/排序；不增加第二精选开关 | 标签既有；运营 P12 |
| `trending` | `trending_7d`，3/6/9/12 | 有真实信号才显示，说明窗口/版本/更新时间 | P9 数据 + P11 |
| `most_viewed` | `views_7d` / `views_30d`，3/6/9/12 | 日去重累计，不冒称独立人数 | P9 + P11 |
| `most_favorited` | `active_favorites`，3/6/9/12 | 当前有效收藏量，撤回即时排除 | P9 + P11 |
| `top_rated` | `approved_ratings`，3/6/9/12 | 真实均分和有效数；应用同一榜单门槛 | P9 + P11 |
| `recent_added` | `created_at`，3/6/9/12 | 只称最近收录 | P11 专用查询 |
| `recent_updates` | `approved_content_updates`，3/6/9/12 | 有公开内容批准事件；不能替换为 latest/newest | P9 工作流 + P11 |
| `legacy_latest` | `existing_updated_at`，3/6 | 兼容现有首页时明确称记录更新时间，不能伪装新 recently updated | 既有，过渡可用 |
| `collections` / `use_cases` | `published_collection_ids` / `published_use_case_ids`，3/6 | 本语言真实已发布实体，资源再过公开门禁 | P11 |
| `tutorials` | `public_latest_tutorials` / `public_tutorial_ids`，3/6 | 同一 Editorial 查询；手选最多 6 个真实教程 | 既有查询，运营 P12 |
| `contribute` / `newsletter` | `localized_editorial` / `consented_newsletter`，1 | 指向已开放投稿流程；订阅只有 P14 可用时呈现 | 投稿现有/P10；订阅 P14 |

空状态策略仅 `show_empty` 或 `hide_when_empty`。服务尚未实现为 `unavailable`，读取异常为 `error`，真实零结果为 `empty`，不混同。后台可显示缺依赖原因；公开用户不见 Phase 编号。配置校验拒绝不匹配的 type/source、超出上限、重复非法实例、任意数据源或不支持 variant。主 Hero/搜索不得同时被关闭而使首页无用途说明/入口；运营若选择其他排列，发布校验仍确保唯一 H1 与搜索可达。

资源卡片只显示真实公开投影；一个 Skill 可在不同有明确语义的模块出现，但同模块必须去重。精选与自然榜单可以同页，必须有不同标题/依据；不能用手选顺序修改 Trending 得分。榜单模块自己的 source 不允许手填分数、排名、浏览数或评价人数。

### 5.4 双语配置、预览与版本发布（P12 计划）

**布局：** WordPress 原生 AI Skills Hub 后台增加“首页配置”入口；左侧有界模块列表（启停、上下移动），中间字段编辑，右侧预览/发布摘要。窄屏变单列，预览独立区域；不是任意画布拖拽建站器。原生表单、nonce、capability、错误摘要和工具栏继续使用 WP 模式。

**组件：** 已开发风格 select、中文/English 编辑切换、模块清单、source select、站内 CTA 选择、桌面/移动预览、保存草稿、发布、版本记录、恢复为草稿。拖拽若增强提供上下按钮和屏幕阅读器排序公告；预览不自动保存/发布。

**状态与并发：**

1. `draft` 独立于当前 `published`。保存发送 `expected_version`，服务比较当前版本（CAS）后递增；旧浏览器保存显示冲突，保留本地输入并要求重新载入/比较，不静默覆盖他人更改。
2. 发布前验证配置版本、权限、语言文案、风格和模块依赖；冻结已校验配置生成不可变 revision，并原子切换 published 指针。发布接收期望 draft 与 published 版本，避免有人在预览后修改内容仍被旧发布请求覆盖。
3. 私有预览使用冻结草稿/版本、同一 renderer 与公开投影；标“预览”，noindex/no-store，需权限；预览可看配置，不因此允许看未审核 Skill。桌面 1440、移动 390 作为预览画布；真实响应式仍检查更多宽度。
4. 模块引用的资源随后撤下/缺译，预览和发布页都立即过滤；发布冻结的是配置，不冻结可绕过公开门禁的内容快照。
5. 中英文分别标完整/缺字段/未发布；缺本语言必填运营标题时该模块不能发布，允许明确关闭它；不自动复制另一语言。站点级风格变更需要两语言兼容检查，保存草稿不影响任何已发布语言。
6. 失败区分校验错误、版本冲突、无权限、保存失败与发布结果未知；未知提交不能显示“发布成功”，先查询当前版本后决定安全重试。公共读取仅采用最后确认成功版本，不读未提交草稿。
7. 恢复历史版本是“复制为新草稿”→重新校验当前公开状态→新发布；不回退版本号、不恢复已撤回内容、不删除新历史。版本记录只保存操作者、时间、配置版本、必要变更摘要，不存密码/token/原始用户数据。

建议有界非 autoload options 保存小型当前/草稿配置；版本历史按受限原生存储设计，不新增首页页面内容库。每份序列化配置建议上限 64 KiB、保留最近 20 个版本，引用只存 ID；具体持久化键/事务/CAS 接入在 P12 实施前与数据设计统一，不在本轮建表或写 option。

### 5.5 排期预留

排期本轮仅预留接口、状态和失败合同，不执行真实定时任务。未来在 P12 首页配置基础上单独获准实施时才开放：

- 输入本地日期时间、明确 IANA 时区和转换后的 UTC；默认使用站点时区，展示名称，不能依浏览器时区悄悄换算。夏令时重叠/不存在时间需明确选择或拒绝。
- 保存 schedule 时冻结确定 revision，不能绑定“届时最新草稿”。同一语言/作用范围最多一个待执行发布，替换须明确取消旧计划；共享风格发布同时验证两语言。
- 状态为 scheduled/running/published/failed/cancelled/expired，记录计划时间、实际时间、修订和执行原因。Cron 延后如实显示，不承诺精确秒级发布；失败不自动把草稿当线上版本。
- 执行时重新验证权限可用性、依赖、配置版本预期与资源公开门禁；期间手动发布使 schedule 的期望 published revision 过期时，计划标冲突并停止，不覆盖新发布。
- 取消与执行采用版本/租约检查；取消成功保证未提交计划不再发布。若已提交则显示已发布并提供“恢复为草稿”，不能假称撤销成功。重试指向相同冻结版本且有界；恢复历史仍生成新 revision。

**验收：** 两编辑同时保存/发布只有符合期望版本者成功；保存草稿不改变公共页；中英不互相覆盖；style 更换不改变查询/SEO；预览无未审核资源。排期阶段须测试时区/DST、延后、取消与执行竞争、手动发布冲突、失败重试及恢复；本轮不执行这些业务测试。

## 6. 中英文、内容与 SEO 合同

### 6.1 三种语言对象分开

| 对象 | 规则 |
| --- | --- |
| 界面文案 | Strings 维护真实 zh_CN/en_US 键；错误/空状态/label/aria/表单反馈都有两种文案。生产不把 key 名或未翻译技术错误输出给用户 |
| 运营内容 | Hero/模块标题/CTA/教程/说明/集合分别维护真实语言；配置完整性独立显示，缺译不复制原文冒充翻译 |
| 用户内容 | 评价保留原文语言并标记；界面切换不复制一份评分或自动翻译。内容过滤改变评价列表，不改变跨语言 Skill 总评分的事实口径 |

Skill ID、用户 ID、收藏、评价不随语言分裂。分类/标签在 P11 前只有共享名称，显示真实名称，不加“已翻译”标志；P11 旁挂译文缺失时可显示原名并明确“名称尚未翻译”，真实译文存在前不伪造对应描述。slug/稳定 ID 沿用；改显示标题不创建新实体。

界面英文允许约 30–40% 文案增幅；按钮/标签可换行但不剪断用途。绝对日期显示本页面语言格式及明确时区；榜单窗口采用 UTC 日期事实，用户不应把本地“今天”误解为另一统计窗口。数值使用本语言格式，不将未知变成 0 或 `—` 而无说明。

### 6.2 SEO 矩阵

| 页面状态 | 索引、Canonical 与语言关系 |
| --- | --- |
| 干净首页/列表/公开完整实体/真实说明页 | 按现有配置可索引；当前语言 self Canonical；只对实际可索引译文输出 hreflang/x-default |
| 合法纯 page 分页 | self Canonical，保留 page；不进 Sitemap，不假称跨语言第 N 页等价 |
| 搜索、筛选、显式排序、窗口参数、未知参数 | noindex/follow/noarchive，规范化有效查询的 Canonical；无 hreflang；robots 不屏蔽其 noindex |
| 缺 About/Contact 真实说明、空分类/标签/集合 | noindex；无伪译文关系，不进 Sitemap |
| 投稿、表单结果、语言 fallback 提示 | 按现有 noindex；结果 Canonical 移除提示参数，不将私人信息拼入 URL |
| 账户/验证/重置/通知/个人记录/私有预览 | noindex/nofollow/noarchive + private/no-store；不入 Sitemap；敏感 token/个人字段不进 Canonical |
| 404/503 | noindex，保持真实状态；无 Canonical/hreflang/实体 JSON-LD |

Meta 统一由 Seo/SeoSettings 输出，主题接管的 Hub 路由继续协调 Yoast、Rank Math、WPML。风格 renderer 不输出 head 标签，不重建 Sitemap 或按卡片数量伪造总数。Skill SEO Title/Description 继续归属现有译文字段及审核流程；不能让运营首页配置替其改文案。

现有 JSON-LD 仅 WebSite/WebPage/BreadcrumbList。P9 后即使出现真实评分，也需单独核查适用 Schema 类型/政策后才能增扩；本设计不承诺富结果，不输出虚构 aggregateRating、作者认证或安全声明。分享图只有真实配置才输出，没有封面不生成虚假的来源截图。
