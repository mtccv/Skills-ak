## 2. 信息架构与布局

后台沿用 WordPress 原生顶栏 `#1d2327`、160px 左栏 `#1d2327`、内容背景 `#f0f0f1`、操作蓝 `#2271b1`。后台默认系统字体 13–14px，正文 `#1d2327`，边界 `#c3c4c7`；标题 23px/400，Metabox 标题 14px/600。紫色只用于 AI 或品牌小标记，不能替代 WP 操作蓝；无营销 Hero、渐变大面板、悬浮胶囊导航或重新绘制的 SaaS 后台。

桌面：32px WP 顶栏；左栏 160px；内容左右 20px；主列/辅助列约 2:1，间距 20px；Metabox 为 1px 边框、0–2px 圆角、无重阴影。Dashboard 为“标题/日期 → 需处理 notice → 统计摘要 → 待办/快捷操作 → 来源及 AI 状态 → 最近活动”。宽度不足 1100px 时分列降为单列；大表允许在表格容器内横向滚动，不产生整页水平溢出。

主菜单结构：Dashboard、Skills（全部/新增/内容审核/分类/标签）、用户（链接原生 Users）、投稿 Inbox、社区评价、举报与纠错、GitHub 采集、AI 生成、运营统计、首页外观、设置。现有 `Reviews` 在中文明确命名“Skill 内容审核”，新用户评分命名“社区评价”，AI 采用过程命名“AI 草稿审阅”；三者不共用状态、计数或批准动作。教程继续原生 `aish_tutorial` 编辑器；用户管理继续 WordPress Users。菜单随能力显示，藏菜单不替代服务端验权。

## 3. Dashboard：从待办进入工作

1. 首屏 title、站点、范围、统一时区、最后成功更新时间；全页样例以固定原型条标记。正式环境不加载本例计数。
2. 需注意 notice：结果不确定的 AI 请求、来源扫描未完成、队列暂停、数据库不可用；含诊断入口和实际阻塞说明。成功通知使用 `notice-success`；警告 `notice-warning`；错误 `notice-error`；状态始终有文字。
3. 四个摘要：Skills 总量（含草稿/归档，不能标成公开数量）、待内容审核数、来源待核实数、AI 待审草稿数。每项显示数据对象/口径/更新时间，点击进入同口径筛选列表。社区数据未上线时显示“未开放”，未知显示“未知”，无记录显示 0；不用增长百分比填充空白。
4. 优先待办用原生 list table：类型、记录/修订、触发原因、队龄/提交时间、处理入口；优先级依证据和人工设置，不以未经审核的举报自动判违规。默认最早待处理优先，可切换级别；高风险线索突出人工核查，不写“已确认攻击”。
5. 采集与 AI 各自 Metabox：队列开关、执行中/重试/需人工处理数量、最近成功时间、下一计划时间或未知；列表显示固定错误码。无真实证据不显示“连接正常”“同步全部完成”“模型验证通过”。
6. 最近活动是授权范围内不可变事件：何人、何对象及修订、何动作、时间、可点详情；不显示 API Key、举报正文、邮箱、原始搜索词。当前基础表不支持完整活动流，正式活动聚合依赖 P9/P12 workflow_events，不从 updated_at 猜测操作者。
7. 快捷操作：新增 Skill、查看待审、采集任务、AI 草稿、首页外观。仅能导航到授权页面；任何排队/发布动作进入完整确认和对象校验。

## 5. 首页外观设置：模板配置，不是页面构建器

位置：AI Skills Hub → 首页外观。这是待实现的产品设计，不改变 `schema 1.5.0` 或当前主题首页。本页用原生设置表单、模块列表、发布 Metabox 和修订记录；不提供拖放任意组件、任意 HTML/CSS/JS、布局代码或自由画布。

### 5.1 单一风格注册与配置边界

style registry 本轮只有 `modern-saas`：标签 **Modern SaaS**，状态“已设计 / 原型可用”，正式主题目前没有 registry。选择控件只能列该条目；不添加“经典/极简/深色”等伪选项。未来新增风格须正式注册受审模板、字段 schema、可访问性及迁移规则，不能把未知 ID 当 CSS 文件路径。`style_id` 站点共享；共享风格变更须将中英两语言一起预览、冻结和发布。

配置只保存有界 JSON/options 或同等受控原生存储（最终由实施规格确定），不新建 Skills、副本译文或用户关系。配置含 `schema_version`、`style_id`、语言内容、已注册模块的 enable/order/source、已批准内容 ID、修订号、操作者与时间。模块 ID 与数据源均白名单；禁止任意查询表达式、URL 获取和脚本。配置记录与公开内容独立，任何配置发布都不能批准 Skill。

### 5.2 模块、内容与双语

模块 type/source/数量上限与实例身份以 [前台设计第 5 节](FRONTEND_DESIGN_SPEC.md#53-独立模块与有界-source) 为共同合同，不另设一份数据源白名单。Hero 与搜索为独立模块，可视觉组合；原型保留两个核心入口不允许隐藏，正式发布至少保障唯一可见 H1 和主搜索可达。其他模块显隐及有限顺序可调整，用“上移/下移”保证键盘可用，拖拽只能是后续可选增强。模块显隐、顺序、标题/描述和 CTA 按 locale 独立配置。

原型仅展示 9 个实例，其通信 ID 为 `hero/search/categories/trending/editors/recent/rated/tutorials/contribute`；这些是静态实例 ID，不替代正式 type。`editors` 对应 editors_picks，`rated` 对应 top_rated，`recent` 对应最近公开内容更新 recent_updates（来源 approved_content_updates），不能用普通 updated_at/采集时间冒充。

按中文/English 维护 Hero 标题/介绍/提示、模块标题/说明、CTA 文案/允许目标。UI 语言与正在编辑的内容语言分开；切换 UI 不覆盖已输入另一语言。缺译给出明确状态，不复制中文充当 English。标题/简介有字符上限、纯文本验证；链接仅允许站内受控路由或已批准目的地。

精选的 source 仅 featured_tag / featured_selection；手选也只能从已有 featured 人工标签且可公开的资源挑选排序，不新增第二精选开关。排行必须使用对应真实算法 source，不能把“自动热门”改名为“编辑精选”。当前尚未上线的排行在正式后台不可选，原型可查看演示状态，不能以示例排名上线。人工选项使用稳定 Skill ID/集合 ID，展示标题、真实语言和当前门禁，不保存正文副本。顺序需给出编辑理由；过期/归档/缺译资源实时过滤，空模块按配置显式隐藏或显示真实空态。

### 5.3 草稿、发布、修订与预览

draft 与 published 是不同不可变修订引用。编辑仅改工作稿；“保存草稿”校验并生成新草稿修订，不影响线上。页面显示当前线上修订、草稿修订、最后保存者/时间和未保存提示。提交必须带 expected_revision；并发冲突保留输入，不覆盖他人新版。

“预览”针对明确草稿修订；中文/English × 桌面/手机四种检查入口，使用实际 SSR 模板、固定宽度容器和当前公开数据门禁。实施时私有预览需能力、短时限授权、noindex/no-store；无效/过期/无权限显示错误，不回退公开假装成功。原型 iframe 只加载本地 `index.html?embed=1&lang=…`，通过同源 `postMessage` 的 `aish-design-home` 白名单协议，把 locale、已知模块 ID/显隐/顺序、受限纯文本标题/介绍投影到当前草稿；不接受任意 HTML、脚本或外部地址，不访问 WP。

“发布”先呈现变更摘要（风格、显隐/顺序、中文/英文改动、不可用引用），校验成功后显式确认。正式实现按当前修订原子切换 published 指针并失效相应缓存。失败保留原线上修订与草稿；成功给出新修订、时间、查看前台入口。恢复历史版本创建新草稿修订，显示差异并重新发布；不覆盖审计历史或自动回滚线上。

### 5.4 未来定时发布与取消/恢复

当前阶段只设计，不实现 Cron。定时发布冻结 config revision、style ID、完整草稿快照、操作者、明确 IANA 时区、UTC 执行时间与本地显示时间；禁止执行时读取“最新草稿”。夏令时不存在/重复的本地时刻必须拒绝或要求选择明确偏移，不能静默换时区。UI 同时显示 `Asia/Shanghai (UTC+08:00)` 和 UTC 时间，用户修改站点时区不改变已冻结任务。

等待中可取消，取消保留任务与草稿；要恢复排期必须重新确认时间与冻结修订并创建新任务，不复活过期租约。定时任务状态 scheduled/running/published/failed/cancelled 为规划值；运行前重新检验能力、配置版本、资源公开门禁和撤稿事件，失败保留当前线上版本。立即发布与定时执行通过版本比较避免旧任务覆盖新发布；重放同任务不得重复发布。原型按钮只说明流程，不启动真实定时器或持久化配置。

## 6. 交互、移动与可访问性

原型 `[admin.html](design-prototype/admin.html)` 及 `assets/admin-prototype.css/js` 仅供设计评审；统一工具条负责五页导航、语言、视口与固定“示例数据”。Dashboard 和首页外观可切换；领域队列入口打开对应规划摘要；模块显隐、上下移动、编辑语言、保存内存草稿、发布确认、恢复草稿与预览均在当前页面内存执行，刷新恢复样例。无 fetch/XHR、无 API、无 cookie/localStorage 业务写入。固定示例值不是生产统计。

小于 782px 时 WP 壳采用 46px 顶栏、菜单按钮和折叠侧栏；一列内容、平板摘要 2 列、手机摘要 1 列、所有操作可换行。正式 WP_List_Table 优先主列与展开详情；AI/Imports 现有 widefat 不自动具备同样折叠行为，比较/日志使用有标签的局部横向滚动。原型表格保留表头与全部状态文字；关键信息不用 hover 才显示。发布区回归正常文档流，不能遮住手机输入/安全区。最窄验收宽度 360px。

语义标题 h1→h2→h3、每字段有 label、状态文字与颜色并用；焦点可见、控件至少 36px（移动 44px）；工具条/菜单 aria-expanded；Tab 顺序与视觉顺序一致。对话框用原生 dialog，打开聚焦标题/首个适当按钮，Esc 关闭并恢复触发器焦点，确认与取消顺序明确；批量操作不可仅图标表达。状态结果用 aria-live，不只 toast。减少动态效果遵循 prefers-reduced-motion。
