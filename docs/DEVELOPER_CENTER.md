# 开发者中心与作者认领

Phase 10 在现有 WordPress Users 上追加受控公开资料和作者/维护者认领。没有独立开发者账户、密码、登录或发布权限体系；默认角色仍为 Subscriber。公开资料、资源认领、用户投稿和 Skill 内容发布是四个独立流程。

## 前台入口与公开范围

| 地址 | 可见范围 |
| --- | --- |
| `/{lang}/account/developer/` | 已验证用户自己的公开资料候选、反馈和认领列表 |
| `/{lang}/account/claim/?skill={skill_id}` | 对当前语言可公开 Skill 发起认领 |
| `/{lang}/account/claim/?id={claim_id}` | 本人的认领材料、结果及允许的撤回 |
| `/{lang}/developers/{handle}/` | 用户主动公开且管理员批准的当前语言资料 |
| `/{lang}/developers/{handle}/avatar/` | 同一批准资料对应的受控头像快照 |

`{lang}` 只支持 `zh` / `en`。最新用户要求采用 `/developers/`，替代规划时的 `/authors/`，不开放原生 WordPress 作者目录作为替代出口。私人路由要求现有登录、邮箱验证、账户状态与对象归属，不接受请求中的用户 ID 指定所有者。

## 申请公开资料

1. 在“开发者中心”填写独立公开 handle、可选 GitHub 主页/网站，并按语言填写真实昵称和简介。
2. 明确勾选“申请公开本资料”。可单独选择公开当前头像快照及经审核的公开投稿贡献；不自动同意营销订阅。
3. 提交后材料进入 Pending，管理员在“开发者资料”页面检查候选稿与已有批准快照，决定批准、拒绝或隐藏。
4. 首次批准后才能公开；已有公开资料重新编辑时，原批准快照继续显示，候选稿不越过审核。拒绝新稿不覆盖旧批准快照。
5. 用户“关闭公开主页”需明确确认，立即停止公开资料、头像、身份链接和贡献投影，保留私人申请/审核历史。

公开 handle 为 3–50 个小写字母、数字、连字符，不允许连续连字符、保留名称、邮箱或内部登录名；审批时持命名锁，通过 WordPress API 更新/核对 `user_nicename` 唯一性。资料文本不得包含账户本身邮箱或内部登录名。审批失败不更改公开身份，不通过直接改原生用户表索引放宽约束。

每种语言支持公开昵称（100 字符）、简介（2,000）、SEO Title（191）及 Meta Description（320）。至少一种语言必须同时具有真实昵称和简介；空语言不复制另一份文本，不调用 AI 翻译，不输出虚假 hreflang。界面语言和材料语言分开，不建立第二个账户或第二个 Skill ID。

GitHub 主页和网站只允许经过验证的 HTTPS URL，不接受凭据、任意端口或本地/IP 目标；链接只作文字/导航，不自动抓取或执行。公开页不显示邮箱、登录名、内部用户编号、未批准稿、私有投稿、管理员备注或认领证据全文。

## 头像

先在原“个人资料”页面管理头像。公开资料申请只引用当前归属本人、经过 Phase 8 重编码的 PNG 头像及其 SHA-256；管理员审核这个快照。后续替换/删除私人头像不会自动发布另一张未经批准的图片，原批准快照不再匹配时回退到通用图形，需要重新提交资料才可公开新头像。

公开头像端点每次核对资料 opt-in、批准语言、账户状态、头像所有权及内容哈希，然后输出受限 PNG。浏览器不能传入附件 ID、文件路径或远程图片 URL；不暴露原生私人头像端点、上传路径或 Gravatar 邮箱哈希。头像同样 `private, no-store`、`noindex`，资料关闭/删除后立即不可访问。

## 身份认领与证据

从某个已发布 Skill 详情的“申请作者 / 维护者认领”进入，选择角色、材料语言、证据类型，填写认领理由及最多 5 个公开 HTTPS 证据链接。只允许公开证据定位，不要提交 Token、私钥、身份文件或私有仓库授权。

| 身份 | 含义 |
| --- | --- |
| Original Author / 原创作者 | 有可核实创作署名、版权/许可署名或其他可靠创作证据 |
| Repository Maintainer / 仓库维护者 | 有可核实仓库维护权，不能自动推定原创身份 |
| Submitter / 投稿者 | 经接受的投稿关联了当前可公开资源，不代表作者或维护者 |

认领材料支持 `authored_source`、`license_credit`、`repository_control`、`other`。仅仓库控制不能申请原创作者身份。服务冻结申请时的 Skill 修订、仓库身份和文件路径；审批再次核对，资源变更后不能批准过期证据。不会自动访问证据链接、执行挑战脚本或扫描用户给出的 URL；管理员人工核实并记录结论。

首版每个 Skill 最多一个主要核实归属，通过数据库唯一键和事务保证；不表示资源事实上只有一位作者。一次申请的证据不可由审核者伪装用户修改。申请人可撤回 Pending、Approved 或 Disputed；拒绝/撤销后的再次申请使用新的证据记录。状态如下：

| 内部状态 | 含义与公开影响 |
| --- | --- |
| `pending` | 待审核，不公开 |
| `approved` | 审核通过，仍须满足资料 opt-in、来源修订及公开内容门禁 |
| `rejected` | 拒绝，不公开 |
| `disputed` | 争议处理中，立即停止公开身份关联 |
| `revoked` | 管理员撤销，立即停止公开身份关联 |
| `withdrawn` | 申请人撤回，立即停止公开身份关联 |

批准、撤销、争议和撤回均记录操作人、时间、原/目标状态、材料修订及用户可见结论，内部备注单独保存。公开查询还要求认领未过期、当前 Skill 修订/仓库与批准证据一致；资源归档、审核失效或当前语言缺译时，页面和 Skill 详情不再输出关联。核实身份不是安全认证。

**认领成功不授予编辑、审核、采集、AI 或发布能力。** 更新说明仍从独立更新建议入口提交，正式 Skill 内容仍由原人工流程决定。用户不能改版本快照、人工译文或稳定 ID。

## 公开展示与 SEO

公开主页展示已批准的昵称、简介、可选头像和链接；关联 Skills 只用当前语言 PublicCatalog 卡片并批量取数、分页。经审核的投稿贡献仅在用户明确同意且结果资源当前公开时展示，标为 Submitter，不混入作者认领。没有关联资源时显示真实空状态，不构造经历、评分或贡献数量。

缺少当前语言批准稿返回不可用页面，并只提供实际存在的其他批准语言链接；没有 opt-in/批准稿或正在删除的用户不公开。英文和中文页面分别使用当前语言 SEO 字段、自引用 Canonical、真实 hreflang 与实际可用 x-default；分页不伪造跨语言页码对应。主题协调 Yoast/Rank Math 标签所有权，真实插件/WPML 验收以阶段证据为准。

私人页面不输出 Canonical/hreflang，不入 Sitemap。公开开发者页面当前通过 Skill 身份链接发现，**Phase 10 未增加开发者专用 Sitemap provider**；既有 Skills/教程/静态 Sitemap 不受影响。所有公开开发者 HTML 暂时 `private, no-store`，防止撤销后共享缓存继续暴露旧身份。

## 原生后台与数据

AI Skills Hub → “开发者资料”（`aish_manage_developers`）与“作者认领”（`aish_manage_author_claims`）使用独立能力、Nonce、状态和服务。管理员可搜索/筛选/分页、查看完整候选/批准版本/证据/处理历史。审批必须逐项核对，不能批量通过；受限批量拒绝、隐藏、撤销/争议最多 20 条，各项独立验权和报告。审批者不能批准自己的身份。

schema `1.8.0` 仅追加 `author_claims` 表，保持原 25 表和 Skill ID。开发者候选、真实双语资料、受保护批准快照和审核历史使用 WP usermeta；不存在 developer_accounts 表。新模型由 `ContributionsModule` 注册，复用 Accounts、Community Events、DAL、Migrator 和原生通知，业务不放入 `functions.php`。

事务内按规范锁序核对身份、预期修订/状态、来源和唯一键，写入不可变申请/审计。请求键绑定操作者、动作和内容；重试不能重复申请或审核，旧页面不能覆盖新资料。主题升级、停用和切换保留数据；用户删除的显式隐私流程则先关闭公开投影，再分批去标识/清理申请资料，不能转交其他账户或删除正式 Skills。

审核结果进入原账户站内通知中心，使用固定中英标题和唯一事件键；不附带私人证据/备注，不声称发送邮件或送达收件箱。隐私导出包括本人的材料及可见审核结果，管理员内部备注不导出给用户。详见 [隐私与安全](../PRIVACY_AND_SECURITY.md) 和 [投稿说明](SUBMISSIONS.md)。

## 测试与边界

HTTP/Nonce/输入/安全返回地址及模板隐私隔离检查在 [`tests/basic/contribution-frontend.php`](../tests/basic/contribution-frontend.php)。领域及真实 WordPress/MySQL/浏览器检查见 [`tests/contributions/`](../tests/contributions/) 和 [Phase 10 报告](PHASE_10_REPORT.md)。隔离检查不能作为真实 WPML/邮件/外部 API 通过证据；开发者链接与证据不因格式合法就表示 GitHub 所有权已经由 API 验证。

本阶段不实现多人团队权限、资源直接编辑、榜单、运营分析、商业化或支付；不自动进入 Phase 11。
