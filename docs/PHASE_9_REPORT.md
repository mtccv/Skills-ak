## 交付范围

- 私有收藏、取消、分页/筛选/首次时间、下架占位和真实计数；跨语言共用稳定 Skill ID，目标状态请求幂等，物理唯一键与事务阻止并发重复。
- 1–5 星、标题/正文/体验/优缺点/平台/可选版本/语言，真实平均分、人数和分布；必须当前邮箱验证，不能代其他用户提交或让管理员/AI 伪造。
- 评价主体与修订独立。Pending 首稿不公开；修改保留旧批准版，批准原子切换、拒绝保持旧版，撤回/隐藏立即去除公开贡献；锁内 CAS 防止过期页面覆盖。
- 原生社区后台、确切被举报修订、审核历史和最多 20 项批处理；与 Skill 发布审核、AI 审稿分开。
- 独立评价举报与 Skill 纠错，管理员处理/结案及固定站内通知；不自动下架，不新增社区邮件。
- 中英文个人收藏/评价、详情评分及评价列表、编辑、举报弹窗、纠错，白灰/陶土棕与既有账户设计一致；原型文件未改。
- 原生隐私导出/恢复清理扩展、最小互动事件及日聚合、真实公开内容批准指纹、受锁保护的有界维护 Cron。

仅在新增 review_revisions 补充本次要求的 title/platform/version_label 字段。原 17 表定义、Skill ID、译文关联、原来源键及私有 Inbox 保持；不创建其他后续阶段表。详细用法与边界见 [COMMUNITY_REVIEWS.md](../COMMUNITY_REVIEWS.md)。

## 发现与修复

| 级别 | 问题 | 修复与回归 |
| --- | --- | --- |
| P1 | 审核通知写入若只锁操作者，可能与收件人隐私擦除交错，在清理后写入新通知 | 所有涉及的账户按数字顺序先锁，再进入 Skill/评价事务；隐私隔离即关闭公开和写权限。社区事务、隐私和并发测试验证 |
| P1 | 冲突的用户元数据或多个隔离标记不能只取第一条解释为允许 | 公开验证证据及隔离条件从数据库判定，存在有效隔离标记即拒绝，当前新写仍复用账户邮箱绑定验证；查询隔离检查覆盖 |
| P2 | 已进入处理中的重复举报可能回报虚假的 Pending，或允许同一活动键换正文 | 读取实际状态并比对载荷；相同请求幂等、不同载荷冲突，结案显式释放活动键 |
| P2 | 社区能力安装早于 admin_init 数据迁移，首次升级菜单延后一请求 | 能力初始化移至迁移之后并刷新当前角色缓存；只增加管理员两项独立社区能力 |
| P2 | 举报详情必须保留被举报的确切修订，不能随公开指针变化显示新稿 | 单独绑定 revision_id 并只读显示该版本，不向仅举报处理角色泄露其他审核备注 |
| P3 | 既有 Skill 详情审核信息面板残留绿色，与当前白灰设计不一致 | 仅将该面板颜色改为现有中性灰 token，保留布局、内容和业务逻辑，重建资源、浏览器和最终 ZIP |
| P2 | 纠错表单失败重试若刷新为最新 Skill 修订，会隐藏旧页面冲突 | 保留提交时修订，服务再次校验，不替用户悄悄覆盖为最新版本 |

测试工具遇到的情况不计为产品通过：QA MySQL 最初不允许创建故障注入触发器，恢复专用测试实例的既定设置后重跑；历史 Core 测试初次选中旧的待删除测试管理员，改为选择仍有真实能力的管理员后再运行；浏览器返回地址原预期未考虑账户系统的 HttpOnly 绑定与清理 URL，按既有安全合同修正断言。未通过的首次尝试不冒充成功。
