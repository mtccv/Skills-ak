# Phase 12 运营指标与隐私口径

## Phase 13 独立展示指标

原运营指标定义保持。赞助采用独立`commercial-1`政策和`sponsor_impression`/`sponsor_click`及日去重桶，不能写入自然浏览、收藏、评分或修改榜单权重。7/30日窗口含当前未完整UTC日，与本文件下方Phase12完整UTC日不同。咨询计量实际保存的私有记录，不将点击或咨询称为购买/收入/转化。具体观察资格、目的同意、预算、保留和失败覆盖见 [商业预留说明](COMMERCIAL_READINESS.md#统计与同意)。

本文件描述实际实现，不代表生产流量、真实邮件送达或外部 API 已通过测试。入口为 WordPress 原生后台 **AI Skills Hub → 运营分析**，独立能力 `aish_view_analytics`；服务层再次验权，无公开统计读取 API。默认不启用观察类采集，沿用发现与首页设置的 `tracking` 发布配置。没有重建统计表，schema 仍为 1.9.0 / 33 表。

## 时间与事实范围

- 选择最近 7 或 30 个**完整 UTC 日**，`start 00:00 ≤ timestamp < today 00:00`；不包含今天。界面显示区间和实际查询时间。
- 当前有效收藏、当前已审核评价、当前验证用户是查询时快照，不套上历史日期标签。
- 注册与投稿基于保留的业务事实，删除/匿名化后历史样本可能减少。未记录的历史浏览、搜索和活跃不回填。
- 指标分别显示实际值、采集未启用、尚未采集、期间早于采集、暂不可用。查询失败不是零。采集起点位于期间中间时标识覆盖不完整；固定错误码按 UTC 日保留最多 31 天的缺口提示。
- 每次查询新事实，不用跨用户缓存。指标写入事件与日桶在同一事务；成功提交后可读。后台日期窗口排除今天是报表口径，不是采集延迟。
- 原生 Users 指标范围是当前 WordPress 用户库（包括多站点共享用户库，如使用 multisite），不是推断的单站成员注册数；资源/搜索使用所选语言。仅 SQL 汇总，无个人行、邮箱或用户搜索记录返回。

## 搜索与身份隐私

成功搜索页面只生成包含 `locale`、真实零结果布尔值、允许保存的短词或 `null`、签发时间和随机请求键的 HMAC proof。未通过敏感过滤的原始词不进入 proof、事件、日桶或日志。客户端不能指定指标名、计数或身份，只能向固定同源 AJAX 操作提交签名 proof 和 WordPress Nonce。AJAX 同时检查请求方法、来源、有效期、UTC 日和长度；查询失败、非法参数和翻页不签发新的搜索证明。

短词最多64 Unicode字符且不超过191字节。过滤邮箱、URL、疑似 API Key/Token/密码/私钥、长数字、电话号码、长标识符、控制字符、标签和无法安全分类的输入。过滤属于保守启发式；不宣称可以识别所有个人信息，未识别风险通过最小保存与频率门槛继续降低。

低频阶段只在 `metric_events` 的 `search_hash` 维度保存按日、站点和语言限定的 HMAC；不保存原词。每词/主体去重键再次使用不同用途 HMAC，不能用某个主体键查询其全部词。**同一UTC日第5个不同观察主体**之后才创建明文合格词日桶，并纳入该日最初5个主体；不能靠单人反复搜索或跨日累计越过阈值。合格日桶 dimension_key 使用规范词的 SHA256 ASCII 前缀 + 冒号 + 显示短词（最多129 Unicode字符，符合原 varchar(191)）；后台验证前缀再解码显示。这避免现有 utf8mb4_unicode_ci 把 `resume` / `résumé` 等不同词误合并，而无需更改数据库表。同词第一次出现后的零结果观察也按主体去重。每UTC日全站最多接纳2000种词/语言哈希，超限仍计站点搜索总量，报告标记词覆盖受限。

观察主体复用 Phase 11 的同一个随机、签名、HttpOnly、SameSite=Lax 当天 Cookie；HTTPS 时 Secure / `__Host-`。新 `.analytics` 用途标记需要明确选择更广的搜索/活跃同意。旧的仅浏览 Cookie **不自动授权**搜索或账户活跃采集。不使用第二个身份 Cookie、localStorage、IP 指纹或登录 Cookie 推算身份。停止按钮移除共享 Cookie，停止浏览、搜索及活跃采集。GPC/DNT、已识别机器人、后台管理/编辑用户、暂停/删除/清理账户及测试标记继续排除。基础规则不能证明真实独立人类或阻挡所有刷量。

活跃用户只使用实际成功登录或已提交的有效账户交互，检查当前真实邮箱绑定 hash、active 状态、用户对象和清理标记；日桶事务前锁定用户行并重读验证证据。HMAC 每日/用途隔离，不保存 user ID、IP、完整 UA、完整请求 URL 或个人历史。统计失败被捕获，不撤销成功业务操作。

## 保留、并发和恢复

- `operations-1` 短期去重事件：7日。低频词只有日哈希且随事件清理，不存在低频明文日桶。
- 合格明文搜索词日桶：30日。其余运营日桶：400日。
- 搜索预算 option：到次日UTC失效，包含每日用途隔离 HMAC，最多100成功观察；同用 bounded Cron 清理。
- 清理复用社区维护计划并支持单个续跑，单次最多200事件、200日桶、100预算；只清理本政策版本/前缀，不清业务数据或其他阶段事件。停用主题只停相应续跑，不删业务数据。Cron 服务停止时物理清理会延后，后台应检查计划可用性。
- 计数使用短期站点命名锁与 InnoDB 事务，唯一事件/日桶键仍是最终约束；命名锁忙不等待长任务，当前观测被跳过并标固定失败日。请求重试同 proof 不再累加。
- MySQL 连接断开不自动重放未知提交。错误只产生日期/固定错误码，绝不记录异常原文、查询词、Cookie、Nonce、proof、Token 或 API Key。
- 覆盖起点与事件/日桶同事务写入；提交/回滚后清除 options 缓存。报表可见少量已确认事实不能证明所有流量都被采集，故障/上限日在界面明确部分覆盖。
